## 攻击意图：奖励配平 + 蒸馏加强（mock 实测）

用户判断："模型没有主动攻击的意图，是'优先找安全路径'造成的；躲避不好是训练不到位；
不要贴角惩罚，应该加大分数奖励，同时以存活为第一要素；加强蒸馏和加强学习。"

### 诊断（关键数据）

规则老师一局（mock 第一面，3196 步）的 `reward_parts` 累计：

| 分量 | 累计 |
|---|---|
| danger | **−3306** |
| stage_clear | +3000 |
| alive | +825 |
| death+miss | −1000 |
| boss_damage | +460 |
| score | **+0.2** |

`score_scale=1e-5`，对准 Boss 每帧只 +4 分 → 一局 2 万分仅值 0.2 奖励，
危险度惩罚是它的 16000 倍。**"不攻击"是权重的必然结果**。

对照（同局面）：站桩 shoot 632 步/636 分/7% 对准；只追 Boss 不躲 743 步/4477 分/59%；
老师 3196 步/20222 分/59%。→ 对准是分数的来源，老师本身会朝 Boss 归位。

另一个关键区分：**BC/DAgger 完全不看 reward**（`_update_batch` 在 teacher 存在时只做
交叉熵）。所以"加大分数"对蒸馏无用；蒸馏的攻击意图来自老师，`GapTeacher` 只看 1D
车道、不看 Boss → gap 线"只躲不打"是结构性的。

### 改动

- `rl/reward.py` 新增 `attack` profile，并**成为 config.json / DEFAULT_CONFIG 的默认值**：
  score_scale 1e-5→3e-2、danger_scale 4.0→0.8、danger_radius 50→32；
  miss −200 / death −600 不变（一次被弹 ≈ 1000 步攻击收益）。
- `EpisodeRecord` 新增 `boss_damage / aligned_steps+boss_steps→align_ratio /
  start_score→score_gain`；`mock_full_clear` 训练日志与 `eval_policy` 打印
  伤害/对准率/净分。
- `mock_full_clear.py` 新增 `--reward-profile` / `--score-scale` / `--kl-anchor`；
  `eval_policy.py` 新增 `--reward-profile` 与观测开关（k-bullets/k-enemies/
  bullet-velocity/danger-grad/no-focus）—— 不匹配会读错 obs_dim。
- **修 bug**：`kl_anchor` 的参考策略只在 `reconfigure` 摘掉老师时冻结，
  "载入蒸馏策略直接 PPO"没有该切换点 → 锚静默为 0。现在 `Trainer.start()` 调
  `_capture_rl_reference()`；`rebuild` 时作废旧锚。回归测试在 test_training。
- 新增 `docs/ATTACK_INTENT.md`；README §6.1、STATUS §0.3/§5/§6、相关文档索引同步。

## 可行域规划器：解决 wall_gate（2026-10-21 晚）

### 做了什么

1. **`touhou_rl_mcp/training/viability.py`**（新）：时间展开的网格反向 DP。
   `cell = speed*dt/2`（dt=2 → 4.4px，轴向 2 格/斜向 (1,1) 格都与真实位移精确相等）；
   `C[k] = 死亡? DEATH+(L-k) : 软代价 + min_{9方向} C[k+1]`；每帧重规划掷第一步。
   参数：`horizon=180, dt=2, kill_radius=5, hard_buffer=2, lead_frames=20,
   soft_weight=0.05, aim_weight=0`。
2. 接进 `TrainConfig`（`planner_horizon/planner_dt`）、`--teacher viability`、
   `tools/pattern_bench.py --policy planner`、`tools/mock_demo.py --teacher viability`。
3. 新增 `tests/test_viability.py`（11 例）：几何精确性、硬危险区、量化吸收、
   不往墙上撞、影子不判死。测试总数 250。

### 四个 bug（都是"能跑但在送死"）

1. `(d_col,d_row)` 写成 `(uy,ux)` → **方向转置**（想往左按了上）。
2. 软危险场 + r=5px 而格子 6.6px → **压在身上只值 0.26 代价** → 永远原地不动。
3. 代价=危险层数之和 → **早死比晚死便宜** → 会主动往墙上撞。改成终止代价。
4. 时间影子当成硬危险 → 100px 外的墙就让全场"必死"。影子只做软代价。
另外：缓冲带只能比硬区多 1 格，否则 48px 缺口在 6.6px 网格上被糊成 1 格。

### 结果（pattern_bench，上限 2000，2 种子）

| | 规划器+对准 | attack_ppo_fixed |
|---|---|---|
| wall_gate | **2000** | 814 |
| closing_ring | 1990（1 死） | 2000 |
| aimed_spread | 1770（1 死） | 2000 |
| 其余 5 种 | 全 2000 | 全 2000 |
| 平均 | **1970 (98%)** | 1852 (93%) |

对准：`aim_weight=0.15` 把对准从 0~20% 提到 61~92%（存活不掉）。

### 下一步

1. 分层切换：常规弹型用策略（对准更高），墙类弹幕交给规划器。规划器 25~40ms/步，
   不能真机 60fps 闭环（`--planner-dt 4` ≈ 7ms）。
2. 只在 wall 片段上用规划器打标签做 DAgger，而不是全局混合蒸馏。
3. closing_ring / aimed_spread 的多方向收网会空局死：软代价需要自适应权重。

## 分层切换：策略 + 规划器（2026-10-21 下午）

### 做了什么

1. **`touhou_rl_mcp/training/hierarchical.py`**（新）：
   - `WallDetector`：只读弹幕位姿的符号判别，0.1~0.3ms/步。
     `curtain` = 匀速下落(vy>=0.7,|vx|<=0.9) + 26px 横带 + 覆盖率>=0.78 + 最大空列<=4；
     `encircle` = 260px 内、>=7/8 方向朝内收缩、距离跨度<=120。
   - `HierarchicalController`：推理期切换（含 `replan_every` 承诺期）。
   - `HierarchicalTeacher`：训练期只在墙段出标签，其余**弃权**（返回空动作）。
2. 接线：`TrainConfig.hier_switch / hier_replan_every / pattern_cycle / planner_aim_weight`
   + `teacher=hier|hier_dagger`；CLI `--hier-switch`（pattern_bench/eval_policy/mock_demo）、
   `--pattern-cycle`、`--hier-replan-every`、`--kl-base`。
3. `policy.imitate_batch` 支持 `actions<0`（无标签，只进 KL）与 `ref_params/kl_coef`。
4. 测试：`tests/test_hierarchical.py`(20) + `tests/test_kl_base.py`(5)，共 275 用例。

### 关键结论

- **切换有效**：8 弹型全部 2000 步（平均 1852→**2000**），`wall_gate` **814→2000**；
  常规关卡 0 次规划器调用（3858 步/6060 伤害/76% 对准，与不开切换一致）。
- **阈值必须量**：第一版覆盖率 0.5 → `dense_ring` 40% 的步误判，对准 90%→79%。
  实测 wall_gate 覆盖 0.94、其余 p95 0.62，卡 0.78。触发率：wall 88.6%、closing 7.1%、其余 0%。
- **训练学不会，因为看不见**（三种口径都试过）：
  A 蒸馏控制器轨迹 → 平均 901（崩塌）；B beta=0 → 1490（崩塌）；
  C `--kl-base 1.0` → 1819（不崩）但 wall_gate 552（更差，对准反而 97%，学成"站住别动"）。
  根因：143 维观测只有最近 16 颗弹，384px 宽的墙/缺口不可见。
- **KL 锚的正确用法**：无标签步只要求"别动"。注意 Adam 动量会让 KL **先升后降**
  （0.19→0.35→0.007），是慢刹车不是一步回位。
- 漂移过的策略（kl1，wall 552）+ 切换 → 又是 2000，切换不依赖策略强弱。

### 下一步

给观测加"墙特征"（16 列占用 + 缺口中心 + 到达帧数），checkpoint 输入层**零初始化扩维**
（新列权重 0 => 函数等价于原策略）。这是唯一能让学生自己学会墙的方向。

## 真机差距归因 + 复刻 replay 弹幕训练（2026-10-21 第四段）

### 归因（docs/REAL_GAP.md）

- 主因是**观测太窄**：k_bullets=16，真机符卡同屏 100~442 颗、replay 平均 ~400 颗
