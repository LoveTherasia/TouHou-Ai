## 1. 一句话

把东方正作（目前真正打通的是 **TH11 地灵殿 1.00a**）封装成标准 RL 环境，并以 MCP
服务器暴露给 LLM Agent：LLM 以 1~10 Hz 做高层决策与调参，本地策略在后台以 60 Hz
执行。核心链路（观测 → 动作 → 奖励 → 训练 → 策略上机）已跑通。

## 4. 已知限制（诚实版）

1. **只有 TH11 能读数值状态**；其余作品只能截图/可视化。
2. **未稳定通关**：真机第一面有过成功记录（`docs/STAGE1_ATTEMPTS.md`，2026-10-17，
   靠规则辅助），但策略单独稳定通关尚未达成；mock 上贪心策略最远到第 2 面。
3. **mock ≠ 真机**：mock 是简化弹幕模拟，通关 mock 不代表能过真机。
4. **实时性**：真机 60 fps 不会等 Agent；低频决策必须用宏动作（`dodge` / `move_to`）。
5. **前台依赖**：按键注入要求游戏窗口在前台；进程崩溃/失焦没有自动恢复。
6. **性能**：每帧批量读约 4.6 MB（2000 个弹幕槽）。
7. **奖励仍有"苟活"空间**：`alive_bonus (0.3) >> |time_penalty (0.01)|`，
   长局里存活收益可能压过通关收益（见路线图 P2）。

#### P2 可行性验证（2026-10-19，实验性）

针对"斥力避弹在环弹下被逼到墙角、不会找缝上穿"做了对照实验：

- 斥力老师 `force` 在 6 种弹型上 `min_y ≥ 358`（场地 448），**最长连续上移仅 13 帧**
  （约 0.2 秒）——行为上限是贴底横移，从不离开下半区。
- 短程规划老师 `horizon` 在 6 种弹型中 5 种于 587~1975 帧内死亡，`y` 被压到 400~440。
- 新增 `training/planner.py`（未来推演 + 宏动作 beam search）与
  `tools/research/gap_benchmark.py`（可复现基准）：
  - 静态单缺口环：规划器能穿出（最大位移 432px），但基准里仍掉 1 残，
    `min_clear=6.2`；参数稍变结果就不稳定。
  - 多层闭合环（新弹型 `closing_ring`）：noop 546 帧、force 582 帧、
    planner 630 帧，全部未过关。
  - 密集环：planner 1500 帧 0 死，但 `mean_y=431`（贴底龟缩）；
    force 在 6 帧承诺下 594 帧死亡。

**结论**：未来推演 + 宏动作是必要组件，但**手写搜索代价不能替代价值函数**。
继续调代价只会在"龟缩 / 贴边 / 冒进"之间换一种失败方式。下一步应直接学习
`V(s)`/策略（future occupancy 观测 + PPO，或用学习到的 V 给搜索做 bootstrap），
而不是继续堆搜索规则。`MacroPlanner` 目前仅作实验脚手架，不接入训练老师。

> ⚠️ 上述结论有一部分被后续发现的 bug 影响：`memory/bullettrack.py` 曾无条件覆盖
> `bullet_velocity`，在 mock 上没有槽位信息时把所有弹速写成 0，导致"时空搜索"实际
> 推演的是一群静止弹。该 bug 已修复（`tests/test_memory_reader.py` 有回归测试），
> `planner.py` 的基准需要在修复后重跑一次才算数。

#### P2 可行性验证 · 二（2026-10-19，缺口任务）

新增 `wall_gate`（真能封死的弹幕墙 + 单缺口）与 `training/occupancy.py`
（时间分层占用栅格 + 每列最早到达时间 TTA 剖面），在 `tools/research/gap_rl.py` 里做
"表示 / 密集信号 / 信任域"三层对照。**结论：几何缺口 + 占用栅格可行**，
但必须配套弱监督与 BC 锚，纯 RL 会坍缩成"不动"。完整数据见
[`docs/GAP_LEARNING.md`](GAP_LEARNING.md)。

#### P2 缺口学习 · 三（2026-10-20，接入正式训练链路）

`GapObservation` / 缺口标签 / 新奖励全部接进 `Trainer`（`use_gap=True`、
`teacher="gap|gap_dagger"`、`reward_profile("gap_survive")`），在 v2 上跑
BC → DAgger → PPO。过程中修掉三个会改变结论的 bug（观测缓冲区别名、车道 12px 对
判定 5px 的盲区使 27% 弹幕不可见、价值回归量级冲垮共享隐层），结果：

- 30 局 BC：748 → **1560 帧**；DAgger：1300~2126 → **2400（3/3）**。
- 四组配置（旧/新奖励 × 旧/新标签）**全部打满 2400 × 3/3**，标签一致率 90~95%。
- **v2 已饱和**（规则缺口跟随能无限跑），奖励/标签的差别只剩"飞行方式"上的小幅差异；
  按赶路时间标定出 `bench v3`（规则基线 ~1800），留给下一轮做真正的对照。

#### P2 缺口学习 · 四（2026-10-20，v3 与训练稳定性）

换到 v3 后同一条流程暴露了三件事，各自对应的改动：

| 改动 | 结果 |
|---|---|
| 域随机化（`--rand`：间隔/弹速/缺口宽度/漂移符号） | 固定场景 1592 → **1830**，最差局 864 → 1368 |
| 多相位评估（`--eval-phases 3`，9 局/次） | 局间极差曾达 900 帧，单相位评估无法区分"学会"和"运气" |
| KL 锚（`kl_anchor>0`） | RL 段不再跌破监督末值，最差局 1014 → 1368 |
| KL 早停估计量修正（`E[(r−1)−log r]`） | 原估计量逐样本可负，`target_kl` 从未触发 |
| 双层 TTA 剖面（`gap_layers=2`） | 维度 70 → 102，RL 段 +34 帧（噪声量级，缺配套标签） |

标签侧结论不变：`future` 更差（1092）、`slack` 与 `reach` 逐帧相同、势函数在 v3 上
是负收益。**当前最优配方 = `reach` 标签 + 域随机化 + KL 锚 1.0**。测试 157 用例。

#### P2 缺口学习 · 五（2026-10-20，P0 评估口径 + P1 决策承诺）

**P0：dev / test 分离**

- `gap_trainer.py` 新增 `--dev / --test / --eval-only / --last`；`policy_best` 只在
  dev 上选，test 只在最后报一次；`meta.json` 分开写 `best / dev / test`，`final`
  明确等于"最后一版在 test 上"。
- 旧 `script-best` 的 2218 是在自己的 3 段选型集上测的；换到从未参与选型的
  `0.76~0.79` 后是 **1984 帧（-10.5%）**，证实选择偏差约一成。
- 新协议：train `[0, 0.55]`；dev `0.56~0.98` 每 0.06 一段（8 段）；test
  `0.59~0.95` 每 0.06 一段（7 段）。窗口互不重叠，但仍来自同一条回放。

**P1：目标承诺 / 滞回 / 动作年龄**

- `GapCommitment` + 有状态 `GapTeacher`（`reach_hold` / `reach_hyst`）；
  `Trainer` 每局新建老师，承诺状态天然重置。
- 观测新增 `gap_action_age`（连续同向步数，1 维，70 → 71），推理时从自己的动作
  计算，不需要老师。
- 评估新增 `--sticky`（推理动作保持）与**策略动作切换率 / 左右反向率**；修掉
  "越过目标列后反向回正"这个会制造新抖动的实现细节。

**第一轮结果**（单条回放，40 BC + 60 DAgger + 40 PPO，5 seeds）：

| 配置 | dev | test | 最差 | 左右反向 |
|---|---|---|---|---|
| `reach` 基线 | 2052 | 2149 | 2079 | 3.8% |
| `reach_hold` 18 帧（修越界前） | 1945 | **2220** | 2079 | 8.9% |
| `reach_hold` 18 帧（修越界后） | 2035 | **2181** | 966 | **1.1%** |
| `reach_hold` 18 帧 + 到达即释放 | 2040 | 2042 | 930 | 3.3% |
| `reach_hold` 12 帧 | 2017 | 2035 | 858 | 5.3% |
| `reach_hold` 30 / 42 帧 | — | 2084 / 2134 | 864 / 972 | 9~11% |
| `reach_hyst` δ=10 | 2002 | 2180 | 858 | 4% |

结论：18 帧承诺在修越界后只抬高约 1.5%，种子间方差很大；更长承诺、滞回、到达即释放
都更差；"少抖"（反向率降到 1.1%）不等于"活得久"。P1 第一版方向对、幅度小，下一步应做
**receding horizon 标签 + 把当前目标列显式放进观测**，而不是继续调承诺长度。
完整数据见 [`docs/GAP_LEARNING.md`](GAP_LEARNING.md)。

#### P2 缺口学习 · 六（2026-10-20，斜向单弹 TTA 修复）

GIF 暴露了一个观测 bug：**斜着朝自机飞来的单颗弹会被标到相邻车道**，自机所在车道
显示"安全"（t1=243），`reach` 标签返回原地，于是站着被撞。

- 根因：`_arrival_times` 取"弹幕刚进入 ±26px 高度带"时的 x；斜弹穿过 52px 高度带
  会横移十几像素（45° 正好 4 条车道），标记的是弹幕上方的位置。
- 修复：取 `argmin |y(t) - player_y|`（穿过自机高度那一帧）的 x 标记车道；
  `tests/test_occupancy.py` / `tests/test_gap_label.py` 各加一个回归用例。
- 合成验证：单颗斜弹从"标签=原地"变为"左/右"。
- `tools/research/aimed_probe.py` 新增单颗斜向自狙探针：旧策略 468 帧，重训 seed 7
  2022 帧；但 seed 17 / 27 仍只有 762 / 468 帧。
- 脚本 test（修复后 3 seeds）：基线均值 2170，`reach_hold` 18 帧均值 **2260**。

**结论：观测 bug 已修，但"单颗自机狙"的稳定躲避还没有解决**——它取决于策略学到的
行为，下一步应把 `aimed_single` 这类弹型放进训练分布，而不是只调观测。

#### P2 方向反思：gap 模仿 vs 反应式策略（2026-10-20）

`aimed_single` 探针给出了一组很清楚的对照（同一天、同一台 mock）：

| 策略 | 单颗斜向自狙 | 4 连 | 密集环 | 环缺口 | 随机爆散 | 弹幕墙 |
|---|---|---|---|---|---|---|
| gap 策略（6 帧宏动作 + BC/DAgger） | 468~2022 | — | — | — | — | 强 |
| 反应式策略（1 帧动作 + 近弹/速度/危险梯度 + rule DAgger，30 局） | **6000** | **6000** | **6000** | **6000** | **6000** | 667 |
| 反应式策略（同上纯 PPO） | 2314 | — | — | — | — | — |

结论：

- **gap 标签只能解决"墙 + 缺口"**，它把 2D 弹幕压成 1D 车道，单颗斜弹的正确响应
  （垂直弹道方向小挪一步）表达不出来；BC/DAgger 的上限就是手写老师。
- **反应式策略能自然泛化到单弹/连发/环/爆散**，但不会为墙提前占位（667）。
- 所以正确方向不是继续调 TTA/承诺长度，而是：**以 1 帧反应式策略为主模型，
  gap/TTA 降级为辅助特征或高层先导**；墙的提前站位用分层/混合策略单独解决。
- 短期目标：多弹型混合 + 域随机化 + 纯 PPO 微调；评估用固定 5 seeds 的
  `aimed_single / aimed_spread / dense_ring / ring_gate / closing_ring / wall_gate`。

#### P2 规划器实测：完整 replay 上的时间展开可行集（2026-10-20）

新增 `tools/research/viability_probe.py`：4px 2D 网格 + 未来 H 层占用 + 反向
`viable[t][x,y]` + 9 方向，不做"离弹越远越好"的代价。

| 片段 | 规划器 (H=120, dt=3) | 站桩 |
|---|---|---|
| 0.59 | **2400** | 1776 |
| 0.65 | 2400 | 2400 |
| 0.71 | **2400** | 1992 |
| 0.77 | **2154** | 2055 |
| 0.83 | 1530 | **2400** |
| 0.89 | 1104 | **1383** |
| 0.95 | 777 | **2166** |
| 均值 | **1824** | **2025** |

- 规划器 **确实会做垂直移动**（动作里出现 `up+shoot` / `up_left`），0.71 从 1992
  提到 2400；说明"时间展开可行集"机制本身成立。
- 在**未来生成完全已知**的环形弹上有效：`ring_gate` 站桩 783 → 规划器 **2400**
  （right/up 组合）；`closing_ring` 546 → 720（有 up/right，但没完全穿出）。
- 但在完整 replay 上整体不如站桩：它看不到未来生成（只外推当前子弹）、有限视界
  没有终端价值、把擦身也当致命、忽略残机/无敌，且 4px 网格 + dt=3 有离散误差。
- 加 `--bottom-prior` 能修 0.83（2400），却把 0.95 打到 726 —— 手写终端代价
  换一个场景就坏，进一步证明需要**学习到的 V(s)**。
- 单次规划约 27~38ms（Python），20Hz 可行，60Hz 还不够。
- 定位：规划器适合做**老师/数据生成器**（上穿、提前站位），或配合学习到的 V 做
  MPC；不能直接当成稳定上线策略。
