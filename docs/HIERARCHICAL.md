# 分层切换：策略 + 规划器

> 一句话：**常规局面用策略（快、会打），检测到"整幅横墙 / 多向收网"时把这一小段交给
> 可行域规划器**。`wall_gate` 从 **814 → 2000 步**（打满窗口），其余弹型的存活和对准不变。

## 1. 为什么要分层，而不是"选一个更强的"

两条路各自都撞到了天花板，而且**撞的地方正好互补**：

| | 学习策略（`attack_ppo_fixed`） | 可行域规划器（`viability`） |
|---|---|---|
| `wall_gate` | **814 步死** | **2000 步**（打满） |
| 常规弹型对准率 | **90~97%** | 61~92% |
| 每步耗时 | ~0.1 ms | **25~40 ms** |
| 真机 60fps 闭环 | 可以 | 不行 |

* 策略的硬限制在**观测**：143 维输入里只有"最近 16 颗弹"的相对位置（+ 8 方向危险梯度）。
  一堵还在 150px 上方、只在远处留一个缺口的墙，**根本不在它的视野里**。所以它注定只能
  "贴到眼前再闪"，而 `wall_gate` 的缺口是 48px、弹间距 9px（钻不过去），来不及。
* 规划器的硬限制在**成本**和**攻击意图**：它把整幅场地 × 180 帧的可行域都算一遍，
  自然会躲，但每步几十毫秒，而且不看 Boss（`aim_weight` 只能算"同样安全时偏向哪一列"）。

所以正确的组合不是加权平均，而是**按局面切换**。

## 2. 判别器（`training/hierarchical.py::WallDetector`）

只读 `GameState` 的弹幕位置/速度，是**符号**判断，一次 0.1~0.3 ms。

**curtain（整幅横墙）**
1. 取出"匀速下落"的弹：`vy >= 0.7` 且 `|vx| <= 0.9`；
2. 只保留"还没越过自机、且在 170 帧内会到达"的；
3. 按 26px 高的横带分组，对每组算：弹数、**横向覆盖率**（24px 一列，共 16 列）、
   **最大连续空列**；
4. 判据：`弹数 >= 14` 且 `覆盖率 >= 0.78` 且 `最大空列 <= 4`（即缺口 ≤ 96px）。

**encircle（多向收网）**
半径 260px 内、距离 >= 42px 的弹里，速度方向与"指向自机"夹角余弦 >= 0.5 的算"朝内收"；
若它们覆盖了 8 个方向扇区里的 >= 7 个、且距离跨度 <= 120px（真的是一圈），就切给规划器。

### 阈值是量出来的，不是拍的

用 `attack_ppo_fixed` 在 6 种局面上逐帧取"覆盖率最高的那一行"（`.runtime/probe_curtain.py`）：

| 局面 | 弹数 p50/p95 | 覆盖率 p50/p95 | y 标准差 p50 |
|---|---|---|---|
| **wall_gate** | **36 / 36** | **0.94 / 0.94** | **0.0** |
| dense_ring | 10 / 12 | 0.56 / 0.62 | 6.4 |
| fan | 9 / 11 | 0.50 / 0.56 | 5.7 |
| stage1（默认） | 8 / 13 | 0.44 / 0.56 | 4.9 |
| ring_gate | 7 / 9 | 0.38 / 0.44 | 5.3 |
| closing_ring | 7 / 7 | 0.19 / 0.31 | 3.0 |

两类局面之间有一大段空白，阈值卡在 0.78。

**踩过的坑**：第一版用 `覆盖率 >= 0.5`，结果 `dense_ring` 有 **40%** 的步、`fan` 有 20%
的步被误判成墙 —— 存活没变，但**对准率从 90% 掉到 79%**（规划器不打 Boss）。
`closing_ring` 的平顶弧在扩张后也会被当成"墙"，同理。

触发率（同一份策略，各跑 1200 步）：

| 弹型 | 触发率 | 原因 | 首次触发 |
|---|---|---|---|
| **wall_gate** | **88.6%** | curtain | 第 55 帧（第一堵墙生成） |
| **closing_ring** | **7.1%** | encircle | 第 60 帧（第一层网收缩） |
| 其余 6 种 + stage1 | **0.0%** | — | — |

## 3. 两个使用面：推理期切换 / 训练期打标签

### 3.1 推理期（真正生效的那一半）

```python
ctrl = HierarchicalController(policy, enc, action_table, replan_every=2)
action = ctrl.act(state)          # 默认 policy.greedy(); 墙段改用 planner
```

* `replan_every` 是**承诺期**：墙段里沿用上次规划方向 N 步再重算。墙在 2~3 帧内几乎没动，
  沿用是安全的，还把墙段成本降到 1/N。
* 接在 `TrainConfig.hier_switch` 上，所以三个入口都能直接用：
  `tools/pattern_bench.py --hier-switch`、`tools/eval_policy.py --hier-switch`、
  `tools/mock_demo.py --hier-switch`。

### 3.2 训练期（`HierarchicalTeacher`）

**只在被接管的步给标签，其余步弃权（返回空动作字符串）**。

这一条是必须的：如果把"策略自己的动作"当标签，交叉熵就变成"让策略对自己更自信"，
会压掉熵、并把墙段的坏习惯固化下来。弃权让梯度只来自真正需要纠正的状态。

`TrainConfig.teacher="hier"`（规划器接管墙段 → 纯模仿）或 `"hier_dagger"`（策略驱动，
墙段拿标签）。两者都不需要人工标注：标签来源就是规划器。

## 4. 实测

### 4.1 分层切换（`attack_ppo_fixed`，8 弹型 × 2 种子，上限 2000 步）

| 弹型 | 不带切换 | **带切换** | 对准率 | 规划器接管 |
|---|---|---|---|---|
| aimed_single | 2000 | **2000** | 96% | 0% |
| aimed_spread | 2000 | **2000** | 93% | 0% |
| fan | 2000 | **2000** | 90% | 0% |
| spiral | 2000 | **2000** | 96% | 0% |
| dense_ring | 2000 | **2000** | 90% | 0% |
| ring_gate | 2000 | **2000** | 94% | 0% |
| closing_ring | 2000 | **2000** | 72%（原 76%） | 7% |
| **wall_gate** | **814（2/2 死）** | **2000（0/2 死）** | 46% | 89% |
| **平均** | **1852（93%）** | **2000（100%）** | — | — |

常规关卡（第一面，8 局）：**3858 步 / 6060 伤害 / 76% 对准 / 规划器调用 0 步** ——
与不带切换（3905 / 6274 / 77%）在同一噪声范围内，**没有代价**。

同种子（101）的逐帧对照：不带切换在 **887 步 game over**；带切换 **活过 1600 步、剩 2 残**。

### 4.2 训练：三种口径都试过，结论是"学不会，因为看不见"

| 口径 | 平均存活 | wall_gate | 常规对准 | 结论 |
|---|---|---|---|---|
| 基线 `attack_ppo_fixed` | 1852（93%） | 814 | 90~97% | — |
| A. 蒸馏控制器（规划器接管墙段执行） | **901（45%）** | 592 | 5~43% | 全面崩塌 |
| B. 策略驱动 + 墙段纠正标签（beta=0） | **1490（74%）** | 657 | 68~82% | 崩塌 |
| C. **KL 锚** + 墙段标签（`--kl-base 1.0`） | **1819（91%）** | **552** | 91~95% | 不崩，但墙没学会 |

A/B 崩塌的原因是**只在该状态子集上做交叉熵**：墙段的状态是"Boss 在场 + 密集弹幕"，
和 `dense_ring` / `aimed_spread` 高度重叠，6 个 epoch 就把那一片映射整体改写
（对准率 90% → 5%，伤害归零）。

C 加了 KL 锚（无标签步只要求"别动"）之后不再崩，但 `wall_gate` 反而更差
（814 → 552），而对准率升到 97% —— 也就是说它学到的是"**站住、继续打 Boss**"。

**为什么必然如此**：143 维观测里只有"最近 16 颗弹"。一堵 384px 宽、36 颗弹的墙，
在观测里只表现为"身边有十几颗朝下飞的弹" —— 缺口在哪**根本不可见**。
在这种表示下，对规划器的动作做监督，最优拟合就是"别乱动"。

顺带一个鲁棒性数据点：把 C 这份"墙段更差"的策略（`wall_gate` 552 步）接上切换，
`wall_gate` 又是 **2000 步（2/2 无死亡）** —— 切换不依赖策略在墙段有多强。

### 4.3 所以当前的分工

* **墙/收网能力靠切换**（不用训练，规则 + 规划器，8/8 弹型满窗口）；
* **训练只做"别把通才弄坏"**：如果一定要在墙段微调，必须带 `--kl-base`；
* 想让策略**自己**学会墙，下一步必须改观测（见 §7）。

## 5. 成本与真机

* 判别器：0.1~0.3 ms/步，**每步都要跑**；
* 规划器：25~40 ms/次，**只在墙段**跑，且按 `replan_every` 摊薄；
* 平均：stage1 全程 0 次规划器调用（触发率 0%），`wall_gate` 约每 2 步一次。
* 真机 60fps（16.7ms/帧）目前**只在"墙段 + `planner_dt=4`（~7ms）"时可闭环**，
  更稳妥的是"墙段降帧数/只接管一小段"。这一点没有在真机上验证过。

## 7. 已知局限与下一步

* **观测决定了上限**：`k_bullets=16` 只覆盖自机附近 ±70px，看不见 150px 外的墙。
  若要让策略自己学会墙段，必须给观测加"墙特征"（例如 16 列占用 + 缺口中心 + 到达帧数），
  并把 checkpoint 的输入层零初始化扩维（旧权重保留、新列权重为 0，函数等价于原策略）。
  这是 §4.2 得到的**唯一**可行方向 —— 继续在旧观测上加标签不会有收益。
* 判别器是**几何**的：只认"匀速直线下压 + 横向密排"。真机里带弧度、带加速的墙会漏判
  （那时会退回策略，不会更差，但也不会变好）；
* `encircle` 的 7% 触发率偏低：`closing_ring` 的下缘会被场地裁掉，扇区数不够。策略本身
  在这个弹型上已经能活满，所以影响不大；
* 规划器仍然"不看 Boss 血量/符卡"，墙段的对准率只有 40% 左右（安全位置里几乎没得选）。
