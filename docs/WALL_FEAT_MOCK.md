# 155 维墙特征在 mock 上的训练验收（2026-10-21）

> **状态：专题记录**。墙学会但遗忘通用弹型，结论见 [`CONCLUSIONS.md`](CONCLUSIONS.md) §2.2。

> 状态：**实验完成，结论是"墙学得会，但同时会忘掉通用弹型"**。
> 代码入口：`tools/mock_full_clear.py --wall-feat --expand-input ...`。

## 1. 设置

- 基线：`.runtime/policies/attack_ppo_fixed.npz`（143 维，9 动作，无 focus）。
- 墙特征：在观测末尾追加 12 维（覆盖率 / 缺口中心 / 缺口宽 / ETA / 8 列占用）。
- 加载时 `--expand-input`：新输入列零初始化，旧策略函数不变，然后继续训练。
- 训练环境：mock `wall_gate`（以及混合弹型），`step_frames=1`，上限 1200 步。
- 验收：`tools/pattern_bench.py`，固定种子，2000 步上限，报均值/最差/死亡/伤害/对准。

## 3. 结论

1. **155 墙特征本身是有效的**：它能看见 384px 宽的墙和缺口，墙专用策略可以打满 2000。
2. **单策略顺序训练/简单混合不足以同时保住墙和通用弹型**：
   - 墙专用 → 遗忘通用；
   - KL 锚 → 不遗忘，但墙学不会；
   - 均衡混合/课程/权重 soup/朴素切换 → 都没有同时拿到两者。
3. **根因不是特征，而是训练分布与状态分布**：
   - 墙专家的训练状态来自自己的轨迹（从回合开始），切到通用策略走到的中局状态后分布不匹配；
   - 通用策略的状态分布又覆盖不到墙段；
   - 单一 256×256 MLP 在 155 维上做多任务，样本效率不够。
4. **当前可用方案仍然是 `hierarchical` + viability 规划器**：8 弹型 2000、墙 2000，
   代价是规划器 25~40ms/步、只在墙段触发。

## 4. 下一步（按优先级）

1. **墙专家做 DAgger，而不是墙专用 BC/PPO**：
   - 用通用策略（`attack_ppo_fixed`）实际访问到的状态作为起点；
   - 在这些状态上让 viability 规划器打标签；
   - 目标：墙专家在"中局/任意起点"也能 2000，再配合切换。
2. **两专家 + 学习门控**：通用专家 + 墙专家，`WallDetector` 只做特征，门控用状态学习；
   目标：8 弹型 2000，且墙专家在切换点不崩。
3. **危险图 + 墙特征正式训练**：当前只验证了维度和 smoke；下一步用 `--grid --wall-feat`
   做 32~64 局多任务训练，对照 `k_bullets` 口径。
4. **若仍无法合并且不遗忘**：接受"墙用规划器/墙专家切换"的工程方案，不强行单策略。
