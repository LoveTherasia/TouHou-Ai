# 规划器 v2：学习型世界模型 + MPC + 蒸馏（设计稿）

> 状态：**方向已定，分阶段实现中**。本文是设计 + 验收口径，实现的代码位置见 §6。

## 0. 一句话

把"手写规则老师"换成**「学出来的动力学模型 + MPC 在线规划」**当数据源，再蒸馏成
1 帧策略，最后用 RL 补规划器**看不到的远期风险**。

## 1. 为什么走这条路

上一节实测（`CONCLUSIONS.md` §2.6）说明三种方法各缺一角：

| 方法 | 会躲单弹 | 会上穿 | 看得远 | 速度 |
|---|---|---|---|---|
| k_bullets 策略 | ✅ | ❌ min_y 325~368 | ❌ 1 帧 | 快 |
| gap 策略 | ❌ 468~2022 | ❌ | ❌ 6 帧宏动作 | 快 |
| 现有规划器 | ✅ | ✅ min_y 44.6 | ⚠️ 200 帧、**看不到未来生成** | 慢（25~40ms） |

现有规划器"会上穿"靠的是**把弹幕按当前速度外推**——这在匀速直线弹上是对的，遇到
加速/曲线弹就失效；而且它每次都要重算整张可达图，慢到无法真机 60Hz。

→ 因此需要：**一个能预测 10~30 帧的学习模型**（比外推准、比模拟便宜）；
**一个采样式规划器**（CEM/MPC，比可达图快、能带奖励偏好）；**一次蒸馏**（把慢规划
变成快策略）；**一次 RL 微调**（补规划器看不到的远期风险）。

## 2. 五层架构

```
            ┌──────────────────────────────────────────────┐
 观测层      │ Deep Sets: 不定长弹列表 → 置换不变嵌入          │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
 模型层      │ f_θ(x,y,vx,vy,dt) → 未来位置 (残差于匀速外推)   │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
 规划层      │ CEM/MPC: 采样动作序列 → 用 f_θ 推演 → 选最优     │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
 数据层      │ (state, planned_action) 大规模收集              │
            └──────────────────────────────────────────────┘
            ┌──────────────────────────────────────────────┐
 策略层      │ BC/DAgger 蒸馏 → PPO 微调（补远期风险）          │
            └──────────────────────────────────────────────┘
```

### 2.1 观测层：Deep Sets（置换不变）

- 每颗弹 → 5 维 `(dx/W, dy/H, vx/S, vy/S, ttc/F)`，`ttc` = 最近接近时间。
- 逐弹映射 φ（**固定随机投影**，维度 `set_embed`）→ 池化 `mean` + `max` → 拼接。
- 子弹是**集合**，顺序无意义；池化保证"打乱顺序输出不变"，且对不定长天然成立
  （`mean/max` 与 N 无关）。
- 与 PPO 的接口不变：仍然输出一个**扁平向量**，MLP 直接吃。
- 下一步可把 φ 也交给网络学（真·Deep Sets），需要策略改成 set-encoder 头。

### 2.2 奖励层：多目标

| 目标 | 项 | 说明 |
|---|---|---|
| 存活 | `alive_bonus` / `miss` / `death` | 保持不变，仍是第一优先级 |
| 进度 | `progress_scale` × Δ(Boss 血量比 + 关卡进度) | 明确奖励"往前打" |
| 分数 | `score_scale` | 已有 |
| 位置偏好 | `position_scale` × (理想站位带) | 惩罚贴角、奖励站在 Boss 下方 |

位置偏好解决"贴底横移也能活满 2000 步"这种退化：**活下来还不够，要站在能打的位置**。

### 2.3 模型层：轻量动力学

- 输入 `(x, y, vx, vy, dt)`，输出**相对匀速外推的残差**：`p' = p + v·dt + f_θ(·)`。
- 参数量：2 层 32 单元（< 2k 参数），单次批量预测 < 0.1 ms（numpy）。
- 训练数据三选一：
  1. **replay 脚本**（`.runtime/danmaku/th11_replay_v2.json`）：匀速弹，只能学到恒等残差；
  2. **锁血真机采集**：`invincible` 开着，逐帧记录槽位 `(x,y)` 序列 → 真实曲线/加速弹；
  3. mock 弹型：同样匀速，用作回归测试。
- 验收：10/20/30 帧预测误差（像素）≤ 匀速外推的 80%（真机数据）；mock 上必须 ≤ 1px。

> 关键认识：**mock 里的弹是匀速直线，动力学模型在 mock 上学不到东西**。
> 这条链的价值完全取决于有没有真机采集的曲线弹数据——这也是为什么先做"接口 + 基线"。

### 2.4 规划层：CEM / MPC

- 决策周期 `dt` 帧（默认 3），视界 `horizon` 帧（默认 24）。
- CEM：在"每步 2D 速度"上采样 `n_samples` 条序列，取最优 `n_elite` 更新分布，迭代 `iters` 轮。
- 代价 = 碰撞硬惩罚 + 最小间距（软）+ 对准项 + 位置偏好项 + 进度项。
- 每步只执行首动作（receding horizon），决策预算目标 < 10 ms。

### 2.5 策略层：蒸馏 + RL

1. 用 MPC 跑大量局面，落盘 `(state, planned_action)`；
2. BC 先学（`trainer --teacher` 已有能力，接一个 `MpcTeacher` 即可）；
3. DAgger：策略自己跑，MPC 对策略访问到的状态重新打标签；
4. PPO 微调：奖励用 §2.2 多目标，专门补 MPC 看不到的"之后才生成"的弹。

### 2.6 替代路线：势能图直接出动作

不训练策略，直接把危险图/占用栅格当**势能场**：`φ(x,y) = Σ exp(-d²/2σ²) + 边界项`，
动作 = 9 邻域里使 `φ` 下降最多的方向（带滞回避免抖动）。

优点：零训练、可解释、能立刻当 MPC 的对照基线；缺点：短视（只有 1 步）。

## 5. 风险与已知限制

1. **mock 的弹是匀速直线**：动力学模型在 mock 上没有增益，M2 只能验证"接口与误差
   上限"；真正收益必须等 M6 的真机数据。
2. **CEM 的代价函数就是新的"老师"**：代价权重写错，MPC 会退化成"躲得远远的不打"，
   所以位置偏好与对准项必须一起给。
3. **蒸馏仍是老师上限**：§2.6 已证明纯模仿 ≤ 老师；M5 必须留 RL 阶段。
4. **Deep Sets 的 φ 是固定投影**：表达力有限，真正端到端要改策略结构（暂不做，
   因为它会破坏"旧 checkpoint 零初始化扩维"的兼容性）。

## 7. 实测结果（2026-10-22，mock 弹型，1 seed，2000 步上限）

| 决策器 | 平均存活 | 满 2000 的弹型 | `wall_gate` | 单步耗时 |
|---|---|---|---|---|
| k_bullets 策略 | — | 7/8 | 814 | 0.05 ms |
| 可行域规划器（viability） | 1970 | 8/8 | **2000** | 25~40 ms |
| **MPC 短视界**（24 帧 / dt3） | 1755 | 5/6 | 548 | 1.2~9.3 ms |
| **MPC 长视界**（72 帧 / dt6 + 缺口项） | 1359 | 2/6 | 1152 | 3~15 ms |
| **自适应 MPC**（按墙检测切换） | **1858** | **5/6** | 1150 | 1~15 ms |
| 势能场（单步负梯度） | 1416 | 2/6 | 1162 | 0.2~0.9 ms |

三条可复现的结论：

1. **长短视界互相伤害**：短视界把反应式弹型全打到 2000 步，但墙只有 548；长视界
   把墙提到 1152，却让 `aimed_spread` 掉到 922、`dense_ring` 1219、`closing_ring` 862。
   原因是长视界把"1 秒后才到的墙"也算进代价，自机开始为它让位，反而在该微调时僵住。
   → 所以有了 `AdaptiveMPCPlanner`：按 `WallDetector` 判别，墙/收网用长视界，其余用短的。
2. **缺口项是墙的关键**：只优化"当前最近距离"时，规划器会站在一堵还远、但必定压下来
   的墙下面（548 步）。加上"正上方弹幕柱"惩罚后 1152。
3. **势能场只能当兜底**：0.2~0.9 ms 很快，但 `aimed_spread` 722、`dense_ring` 794，
   对准率 3~5% —— 单步负梯度天然会"往空旷处跑"，不会做多步站位。

**仍未达到 viability 的 2000**：MPC 的 CEM 在 8 个方向上采样，找不到"提前 1.5 秒横移
到缺口正下方"这种跨越整个视界的承诺；viability 的可达图 DP 恰好擅长这个。
下一步把墙段的"缺口中心 + 到达时间"直接接进 MPC 代价（而不是靠弹幕柱隐式表达）。

## 8. M4 收尾：三个"看起来能用、实际不能用"的坑（2026-10-22）

这一节全是实测踩出来的，改了之后才让 MPC 具备当老师的资格。

### 8.1 缺口项：从"可达性"改成"锚点"

第一版按"可达性"写：`slack = 该列被封锁的时刻 − 赶过去要的帧数`，slack 越小越危险。
**完全无效**（wall_gate 1144 步，和不加一模一样，权重 2/6/15/40 都一样）。原因：

* `wall_gate` 的墙在 y=108 生成、以 1.9px/帧下落，到自机高度要 **146 帧**，远长于
  72 帧视界。视界内它"还没到"，于是**每个候选终点的 slack 都很大**，代价地形完全平坦。

改成**锚点**：显式找出最近一堵墙的缺口中心 `x_gap`，代价 `= |x_end − x_gap| / 场地宽`。
"是不是墙"用两个门槛判定（同一时刻穿越事件 ≥ 8 颗、封住 ≥ 50% 的列），稀疏射击
（自机狙）不会触发，避免把自机拽去一个毫无意义的"最宽空档"。

还有一个反直觉的细节：锚点要瞄**视界之外**最近的那堵墙。瞄最早一堵时，墙每次穿过
自机高度的瞬间目标会突跳 61px（缺口每 55 帧横移 0.17×360），自机永远差一拍 ——
实测 1144 步，改成瞄视界外之后 1028~1090（有改善但幅度有限，见 8.2）。

### 8.2 连续时间安全余量：粗步长会"穿透"（真 bug）

长视界必须用粗步长（dt=12），否则 CEM 的维度爆炸。但原来只在**采样时刻**算距离：
一颗弹每步走 1.9×12 ≈ 23px，而判定直径只有 10px，采样点全部落在"擦过去"的空隙里，
规划器以为自己安全。实测 `wall_gate` h180/dt12 只有 **648 步**，比短视界（548）还差一点。

改成对每段相对运动**解析求最近接近距离**（二次式，与 dt 无关）：

| 配置 | 改前 | 改后 |
|---|---|---|
| wall_gate，h180/dt12 | 648 | **1042** |
| wall_gate，h180/dt12 + 缺口锚点 | 684 | **1048** |
| aimed_single / spread / dense_ring，h24/dt3 | 2000 | 2000（不变） |

结论：**MPC 的步长可以粗，但距离判定不能粗。**

### 8.3 当老师时的两个静默错位（会让训练直接崩）

`training/mpc_teacher.py` 只做适配，但踩了两个坑：

1. **动作名格式**：MPC 输出 `up+left+shoot`，而 `trainer.DIRECTIONS` 是 `up_left`。
   不转换的话 `_teacher_index` 解析失败 → 全部落到"不动"，等于教学生站桩。
2. **时间单位**：MPC 的运动模型是"每决策 1 帧 × 4.4px"。`step_frames=4` 时不换算，
   它以为自己每步走 4.4px、实际走 17.6px —— 它算出的"安全位"根本来不及到。
   实测存活 **140 步**；把自机速度、弹速同时 ×4、并按帧换算视界后回到 **800 步（满）**。

### 8.4 真机轨迹采集与动力学（M6，首个真实收益）

`tools/collect_tracks.py`：锁残机（`memory.cheats.LivesLock`）+ 规则老师跑动，
按**槽位号**逐帧记 `(frame, x, y)`，一帧跳 30px 以上判为槽位回收并断开，
中心差分出速度、二阶差分出加速度，输出 `{"tracks": [[[x,y,vx,vy,ax,ay], ...]]}`。

2026-10-22 采 75 秒（TH11 第一面）：

| 指标 | 值 |
|---|---|
| 轨迹 / 点 | **844 条 / 117 124 点** |
| 单帧速度 中位 | 2.50 px/帧 |
| 明显弯曲（>0.5°/帧）的轨迹 | **29.4%** |
| 每帧转向 90 分位 | 4.00° |

动力学训练（`tools/train_dynamics.py --tracks`，视界 10/20/30 帧）：

| 模型 | MAE | 3 帧 | 6 帧 | 10 帧 |
|---|---|---|---|---|
| 匀速外推 | 1.899 px | 0.39 | 1.48 | 3.92 |
| **残差 MLP（322 参数）** | **0.844 px** | 0.45 | 0.70 | **1.40** |

**相对匀速外推 44%**，10 帧视界好 2.8 倍 —— 这是这条线上第一次出现真实增益
（mock/replay 都是匀速直线，残差恒 0）。模型已接进规划器：
`pattern_bench.py --mpc-dynamics .runtime/dynamics/real_01.npz`。在 mock 上不损伤
（aimed_single/dense_ring 仍 1000/1000）。


## 9. M5：把 MPC 当老师蒸馏（2026-10-22）

### 9.1 先把老师的水平量清楚（同循环、同起点、step_frames=2）

`MPCTeacher`（自适应视界 72/24 + 缺口锚点 20）在 6 个弹型上各跑一局 1200 步：

| 弹型 | 老师存活 |
|---|---|
| aimed_single / aimed_spread / dense_ring / ring_gate / closing_ring | **1200（满）** |
| wall_gate | 581 |
| **平均** | **1097** |

### 9.2 硬标签蒸馏：学生停在 600 步，怎么也上不去

| 实验 | 观测 | 承诺期 | 老师带飞 | 贪心（6 弹型均值） |
|---|---|---|---|---|
| BC1 | k_bullets 32（239 维） | 1 | 1100 步 | 596 步 |
| BC2 | k_bullets 32（239 维） | 3 | 950 步 | 601 步 |

两轮都是 120~150 局、9 动作、lr 3e-4。学生稳定在老师的一半，且**实验二没有变好**。

### 9.3 根因：不是没学会，是"标签本身是噪声"

同循环逐帧对比（学生贪心 vs 老师标签）：

| 弹型 | 学生存活 | 老师存活 | **动作一致率** |
|---|---|---|---|
| aimed_single | 580 | 1200 | 22.6% |
| aimed_spread | 421 | 1200 | 20.2% |
| dense_ring | 430 | 1200 | 17.9% |
| ring_gate | 571 | 1200 | 21.2% |
| closing_ring | 270 | 1200 | 20.7% |
| wall_gate | 269 | 581 | 16.7% |
| **平均** | **423** | **1097** | **19.9%** |

再量老师**对自己**的一致率（同一批状态，两个 CEM 随机种子）：

| 弹型 | 自一致率 | 相邻帧换动作比例 |
|---|---|---|
| dense_ring | 21.2% | 76.7% |
| wall_gate | 22.5% | 77.4% |
| closing_ring | 21.2% | 78.6% |

**学生的 19.9% 基本等于老师自一致率的 21%** —— 它已经学到了老师身上"可学的那部分"，
剩下的 80% 是 CEM 在"多个动作同样安全"时的随机 argmax。硬标签蒸馏的天花板就在这里。

（补充：给 CEM 加**热启动**——用上一步的精英均值当初始均值，滚动优化的标准做法——
相邻帧抖动从 77% 降到 **50%**，但自一致率仍是 ~25%。也就是说抖动只是表象，
并列动作的随机选择才是本质。）

### 9.4 对应的修法：软标签

既然"代价接近的动作"本来就该一起学，就把老师的**逐动作代价**变成目标分布：

```
p(a|s) = softmax( -cost(s, a) / T )
```

`MPCPlanner.action_costs(state)` 只做**一次** rollout（9 个动作各一直按着），比 CEM
便宜一个量级；`Trajectory.soft` 存这个分布，`MLPPolicy.imitate_batch` 检测到
`(N, n_actions)` 的二维目标就改用 KL/交叉熵软目标（梯度 `p − target`）。
开关：`--soft-labels --soft-temp 20`（`TrainConfig.soft_labels / soft_temp`）。


### 9.5 软标签 / 换观测的实际结果：都没有突破

| 实验 | 观测 | 标签 | 局数 | 老师带飞 | 贪心（6 弹型均值） |
|---|---|---|---|---|---|
| BC1 | k_bullets 32（239 维） | 硬 argmax | 120 | 1100 | 596 |
| BC2 | k_bullets 32 | 硬 argmax + 承诺期 3 | 150 | 950 | 601 |
| **BC4** | k_bullets 32 | **软标签**（T=20） | 120 | 1090 | **619** |
| **BC5** | **缺口/占用栅格 822 维** | **软标签** | 120 | 1090 | **570** |

- 软标签比硬标签好一点点（619 vs 596~601），但**没有质变**；
- 换成规划器同构的 822 维观测反而更差（570）—— 说明在这个样本量下，
  **瓶颈不是表示能力，而是"从规划器到策略"这条映射本身很难用 12 万步拟合**；
- 与老师的对比始终是 **570~620 / 1097 = 52%~56%**。

### 9.6 结论与下一步

**"MPC 当老师 + BC 蒸馏"这条路在 120 局规模上不通**，两个原因都可量化：

1. **标签噪声**：老师自一致率 ~21%、相邻帧抖动 50~77%，硬标签的天花板就是 20~25%
   一致率；软标签解决了噪声，但只换来 +3% 存活。
2. **样本量**：12 万步对"9 动作 × 239 维、且要在密集弹幕里做长程站位"的策略远远不够
   （对比：replay 上纯模仿用了 44 万步才到 8.6k 帧）。

真正可行的替代顺序（按性价比）：

1. **先让老师确定化**再蒸馏：`iters`↑ + 固定 CEM 随机种子 + 对并列动作做"承诺"
   （连续 N 帧不允许换向）。这是把噪声从源头掐掉，比换标签形式更直接。
2. **改成学"代价"而不是"动作"**：让学生输出 9 个动作的 cost-to-go，用老师的
   `action_costs` 做回归 —— 等价于把 MPC 的价值函数蒸馏出来，再由学生自己 argmax。
   这条对并列动作天然免疫（代价接近 → 学生输出也接近）。
3. **样本量**：局数至少 500+，或者直接把 MPC 放到"需要它的局面"（墙/收网）上采样。
4. 其它里程碑（M1~M4、M6）已完成，`docs/CONCLUSIONS.md` §2.8 有汇总。

## 10. M5 重做：老师确定化 + cost-to-go 蒸馏（2026-10-22 晚）

§9.6 列了三条修法。这一节把它们真正实现并量了数 —— **结论：老师那一侧确实被修动了
（换向率减半、标签口径与老师动作 100% 对齐），但"能不能学到通关"还没有被证明**，
下面的表先把"老师是否还抖"这件事钉死，再谈学生。

### 10.1 三处改动

| 位置 | 改动 | 为什么 |
|---|---|---|
| `mpc.py` `commit_steps` / `switch_margin` | 选定方向后 N 帧内不换向，除非新方向便宜 `switch_margin` 以上 | 代价平坦处 CEM 每帧翻方向（实测换向率 51.8%），这是"标签噪声"的源头之一，也是真机手抖 |
| `mpc.py` `deterministic` | 每帧用 `seed + frame` 重播种 CEM 噪声 | 同一帧不再受"这是第几次调用"影响；自一致率测量才排除 RNG 序列漂移 |
| `mpc.py` `action_costs(mode="plan")` | 代价口径从"该动作按满整段视界"改成 **"先走这一步 + 接着走 CEM 剩余路径"** | 这才是滚动优化下执行某动作的真实代价。旧口径下老师动作与 `argmin` 只有 **48.9%** 一致 —— 教的和做的不是同一件事 |
| `mpc.py` `focus_speed` | `speed × 2/4.4`，随 `step_frames` 一起 × k | 原来写死 2.0，`step_frames=2` 时老师以为半步 2px、实际 4px，算出来的"半步位"全错 |
| `mpc.py` `action_costs(focus=True)` | 返回 **18 维**（9 快 + 9 慢），慢速块按半速 rollout | 真机慢速键（Shift）必须进动作表，否则学生学不到"半步走" |

`choose()` 也顺势改成 **逐动作 cost-to-go 的 argmin**（不再量化 CEM 连续解）：
老师做的动作、老师给的标签、学生 argmax 三者同一口径。

### 10.2 老师到底稳了多少（`tools/teacher_check.py`）

同一批状态（`RuleTeacher` 驱动 3 个弹型各 120 帧，`step_frames=2`），两套 CEM 种子：

| 口径 | 换向率 | 自一致 | 标签换向 | 标签自一致 | 动作≈argmin | 代价间隙 |
|---|---|---|---|---|---|---|
| hold，iters=3（旧） | 61.1% | 22.5% | — | — | **48.9%** | 65.3 |
| plan，iters=3 | 51.8% | 38.1% | 51.8% | 38.1% | **100%** | 28.2 |
| plan，iters=5 | 45.4% | 33.6% | 45.4% | 33.6% | 100% | 38.5 |
| plan，iters=5 + commit 3 / switch 5 | **27.2%** | 36.7% | 45.4% | 33.6% | 80.3% | 38.5 |

三个可读的结论：

1. **换向率能砍一半**（51.8% → 27.2%），全靠承诺期。代价是对准率略降
   （`aimed_single` 52% → 42%），因为"转向对准"的收益远小于 `switch_margin=5`。
2. **承诺只改老师自己的动作，不改标签**：加承诺后"标签换向"仍是 45.4%。
   想让标签也带滞回，得在代价向量上做（未做）。
3. **标签自一致只有 33~38%**：同一状态换一个 CEM 种子，`argmin` 会有 6 成变。
   这是剩余噪声的主要来源（代价并列 + 视界内无差别）。**argmax 分类会被它彻底带偏，
   而回归 cost-to-go 不会** —— 并列时目标向量本身只差一点点，MSE 的误差也就一点点。
   这正是下面改用回归、而不是"硬/软标签"的理由。

focus 打开时（同一配置）：focus 使用率 **46.9%**（密弹里老师确实一直在半步走），
`动作≈argmin` 80.8%，代价间隙降到 15.4 —— 18 个动作分摊了并列。

### 10.3 cost-to-go 回归怎么做（`MLPPolicy.fit_cost`）

```
target_logit(a) = -clip((cost(a) − min cost) / T, 0, clip)      # T=soft_temp, clip=cost_clip
loss            = weighted MSE(logits, target)                  # 加权 = danger_weight
```

与 §9.4 软标签的两点区别：

- **梯度不饱和**：软标签用交叉熵，目标一旦饱和成 one-hot，梯度 `p − target` 就趋零；
  MSE 的梯度是线性的 `logits − target`，代价差 10 倍时梯度也大 10 倍（被 `clip` 封顶）。
- **保留绝对差距**：交叉熵只对"谁更好"敏感，MSE 还知道"好多少"。

链路：`MPCTeacher.cost_vector(state)`（18 或 9 维）→ `Trajectory.cost` → `Trainer._update_batch`
→ `MLPPolicy.fit_cost`。开关：`--cost-to-go --cost-clip 8`（`TrainConfig.cost_to_go / cost_clip`），
温度复用 `--soft-temp`。日志里多两项：`cost_mae` 与 `argmin一致`（学生 argmax vs 老师 argmin）。

### 10.4 学生真的学过去了吗

> 6 弹型轮换、纯模仿；评测用 `pattern_bench` 6 弹型均值）。

| BC4（§9.5） | 239 | 软标签 T=20 | 9 | 120 | 619 |

| **CG-f** | 239 | **cost-to-go** + focus | 18 | 120 | 见 10.5 |

### 10.5 结果（同口径：120 局 / 900 步/局 / 6 弹型轮换 / 纯模仿 / 5 seeds 贪心）

评测协议与 §9 的旧表不同（旧表没有留存 bench json，口径不可考），所以这里**先用同一协议
重测了 §9.5 的软标签策略** `.runtime/mpc_soft1/policy.npz` 作为控制组：

| 弹型 | 软标签 BC4（控制组） | CG-nf（9 动作） | CG-f（18 动作，带 focus） |

| **均值** | **637** | 489 | 514 |

三件事：

1. **cost-to-go 没有赢**（489 / 514 vs 637）。它不是全面变差，而是**换了强弱分布**：
   dense_ring +45、closing_ring +252，但把 ring_gate 从满 1200 掉到 ~500。
2. **focus 是这轮唯一质变**：`aimed_single` 从 765 → **1200（5/5 满，伤害 1544）**。

### 10.6 为什么回归学不进去：目标是"并列 + 饱和"的

对同一批状态统计老师代价向量的形状（`step_frames=2`，视界 72）：

| 弹型 | 最优与次优的间隙中位数 | 严格并列的帧 | 平均 \|相对代价\| | ÷T=20 后 |
|---|---|---|---|---|
| dense_ring | **0.00** | **78.3%** | 378 | 18.9 |
| ring_gate | **0.00** | **74.2%** | 308 | 15.4 |
| wall_gate | **0.00** | **51.7%** | 324 | 16.2 |

也就是说：**七成以上的帧，最好的动作和好几个动作代价完全相等**（都是"足够安全"），
而其余动作的相对代价动辄 300+，除以 T 后是 15~19，早就撞到 `cost_clip=8` 的封顶。
于是目标向量实际只有两种取值：**0（并列最优）和 −8（明显危险）** ——
这已经不是"连续代价"，而是一个带并列的 one-hot。

后果很直接：

- 回归相对交叉熵没有任何优势（信息量一样，都是"哪几个安全"）；
- 学生只能学出"这几手都行"，argmax 落在哪个上取决于浮点误差 —— 于是 `argmin一致`
  卡在 21~26%（9 动作）/ 7~9%（18 动作）；
- 连"背下小批数据"都做不到：2 局 800 步、200 epoch、lr 3e-3、128×128，
  `argmin一致` 只到 35%，`cost_mae` 1.5（目标量级 0~8）。

要让 cost-to-go 真正有用，缺的不是样本量，而是**一个连续的代价**：

1. 代价函数里加"平滑安全余量"（如 `w·exp(−min_clear/σ)`），让"离弹 12px"和"离弹 30px"
   代价不同 —— 现在两者都是 0（只要过了 `clearance_margin`）；
2. 或者把回归目标改成**并列感知的排序损失**（同代价集合共享目标概率），
   本质上就退回软标签，但要显式建模并列；
3. 温度/截断要按代价的实际分布定（现在 T=20、clip=8，等于把所有 >160 的差距压平）。

| 代价口径改成"一步偏离 + CEM 续接" | 已实现，`argmin` 与老师动作 100% 一致（旧口径 48.9%） |

## 11. 并列感知排序损失 + 规划器同构观测（2026-10-22 深夜）

§10 的结论是"回归学不进去，因为目标是并列+饱和的"。这一节按那个判断做了两处替换，
**其中一处成了这轮最好的结果**。

### 11.1 换掉了什么

| 项 | 原来 | 现在 |
|---|---|---|
| 蒸馏损失 | 回归 `-clip(rel/T)`（MSE） | **并列组共享目标质量的 CE**（`MLPPolicy.fit_rank`） |
| 观测 | 239 维（最近 32 颗弹） | **822 维**（缺口栅格 + 几何 + 通道余量 + 前向动作，`--gap --gap-layers 2`） |
| 开关 | `--cost-to-go` | `--rank-ties --rank-margin 20` |

### 11.2 并列感知排序：先试成对 RankNet，失败了

第一版按 RankNet 做：对"代价差 > margin"的动作对 (i, j) 用 `softplus(−(logit_i − logit_j))`。
问题出在正例的选择：只拿 `argmin` 当正例时，**并列组里没被选中的那个永远得不到强化**，
实测并列的两个动作的 logits 被拉开 **1.1**（`test_tied_group_*` 一开始就是这么挂的），
等于偷偷把"并列"改成了"必须挑第一个"。而且负例采样用固定种子时，这种偏向会被系统性放大。

### 11.3 现在的做法：并列组当作"一个答案"

```
good(s) = { a : cost(s,a) ≤ min_a cost(s,a) + margin }     # 并列最优集合（常含 3~4 个动作）
target  = 在 good(s) 上均匀，其余动作 0
loss    = CE(softmax(logits), target)                      # 梯度 p − target
```

- **对称性天然成立**：并列组内共享同一份质量，不会出现"谁先谁占便宜"；
- **只用有信息的差别**：差在 `margin` 以内的都是"一样好"，超过的只要求"别被选中"，
  不要求它们之间的相对顺序（那些顺序本来就被截断压平了）；
- 与软标签 `softmax(-cost/T)` 的区别：目标不是温度平滑的分布，而是**显式按 margin 归组**，
  并列组得到完全相等的质量（软标签在并列处仍有微小梯度噪声）。

指标也换了口径：

* `rank_acc`：学生 argmax 落在并列组内的比例 —— 这才是这个损失真正在优化的东西；
* `agree`：与严格 `argmin` 的一致率 —— 并列组平均 3.8~4.4 个动作，随机选的上限本来就只有 ~25%。

### 11.5 判读

1. **换成排序损失是这轮最有效的一步**：同观测、**少 50 局**（70 vs 120），均值 583 vs 489；
   `rank_acc` 从"接近随机"（21~26%）跳到 **70~74%** —— 说明"并列组共享目标"确实让
   学生把老师的安全集合学进去了，而回归只是学会了"都差不多"。
2. **叠加 focus 后首次超过软标签控制组**：**678**（70 局，18 动作）> 637（120 局，9 动作）。
   `dense_ring` 359 → 770、`ring_gate` 1200/807，且 `aimed_single` 满 1200。
3. **822 维观测没帮上忙**：`rank_acc` 最高（77~91%，说明拟合得更贴）但存活 567 < 583。
   和 §9.5 的 BC5（822 维软标签 570）一致 —— 观测越大学生越难在 6~10 万步里拟合，
   而且规划器的缺口表示本来是给"规划"用的，给"反应式策略"反而更难内化。
4. **margin 不是关键旋钮**：20 与 5 的均值 583 vs 580 几乎相同，只是强弱互换
   （`ring_gate` 526→1128、`aimed_single` 1147→843）。关键是"允许并列"这件事本身。
5. **继续训练不涨**：同样配置续到 120 局，`rank_acc` 升到 73~77% 但存活 558 < 583 ——
   **更贴老师的代价 ≠ 更会活**。老师的代价里没有"对准/输出"项，越贴它越保守
   （排序+focus 那组的对准率只有 2~19%），这也是下一步该补的地方。

## 12. 方向复核：v2 哪些判断被证实、哪些被推翻（2026-10-22 深夜，收束）

这一节把 §7~§11 的全部实测按"设计假设"重新归一次类。结论先给：

> **架构方向正确，但"正确"的范围比设计稿写的窄。**
> 「规划器 = 能力上限」「慢动作是必需品」「并列是蒸馏的核心困难」「学习型动力学是真机增益来源」
> 四条被数据支持；「cost-to-go 连续价值可学」「观测越像规划器越好」「加数据就会涨」
> 三条被推翻；**「蒸馏 + RL」这条主线的 RL 那一半从来没跑过**，
> 所以现在的 56.5% 是**设计里预期的阶段性上限，不是"路线失败"的证据**。

### 12.1 五层各自的裁决

| 观测 | 规划器同构的缺口栅格（822 维）能帮策略 | BC5 570、排序 822 维 567，**两次都低于 239 维的 583** | ❌ 推翻 |
| 奖励 | 多目标（进度/分数/位置）防"贴底横移刷存活" | 已实现，**但 M5 全程纯模仿，奖励一次没生效** | ⏳ 未验证 |
| 模型 | 学习型动力学比匀速外推准 | 真机 11.7 万点，MAE **1.899 → 0.844（44%）**，10 帧 3.92→1.40 | ✅ 证实 |

### 12.2 三条被推翻的假设，各自的教训

| 假设 | 推翻它的数字 | 教训（下一版设计要写进前提） |
|---|---|---|
| 逐动作 **cost-to-go 回归** 比分类/软标签好 | 238 帧里 **74~78% 最优与次优完全并列**，其余相对代价 300+ 全部撞 `clip=8` → 目标退化到 {0,−8}。回归 489 < 软标签 637 | **老师的代价是"约束满足"型（过了阈值一律 0），不是"优化"型。约束型代价里没有可回归的连续价值** —— 要么先给代价加平滑余量，要么别做回归 |

### 12.3 三个"设计里有、实际断掉"的环节

这三个都不是结论，而是**链路断点**——它们让"v2 已经失败"这个判断暂时不成立。

**① 动力学模型（M2）没有接进蒸馏（M5）。**
`pattern_bench.py --mpc-dynamics` 能接，但 `trainer.py` 构造 `MPCTeacher` 时不传 `dynamics`，
`mock_full_clear.py` 里干脆没有这个参数。所以**"学出来的模型参与规划"这条主线，在产数据那一侧从未生效**；
老师一直用的是 `ConstantVelocity`。mock 是匀速弹、接了也没用，但真机 replay 复刻（`danmaku_script`）里
这条是断的。

**② 老师的代价函数里没有"要打"。**

上一版这里只写了"量级太小"。收束时实测了一遍，问题比量级更彻底 —— **瞄准项在大部分帧里根本不存在**：

| 检查 | 实测 |
|---|---|
| 瞄准项生效条件 | `if boss := raw["boss_position"]`（`mpc.py:314`）—— 没有就直接跳过 |
| mock 里 boss 何时出现 | **第 292 帧**（`aimed_single`，`step_frames=1`）；开局几乎无 boss |
| 300 帧内 boss 可用率 | **8 / 300 = 3%**（400 帧统计 27%，因为越往后越有） |
| 有 boss 时的瞄准项上界 | `0.35 × |Δx| / 384 × 10`，最大 **3.5** |
| 同时的安全项量级 | 碰撞 `200 + 50·|pin|`；缺 margin `8·deficit²`（deficit=10 → **800**） |

**双重失效**：`step_frames=2` 时前 ~146 决策步（约 16%）**完全没有瞄准项**；
其余帧里瞄准项的权重比安全项小 **60~230 倍**。合起来就是一个纯躲避老师 ——
这直接解释了对准率 **2~19%**，也解释了 §11.5 第 5 条"续训反而更差"
（越贴老师，越学会"躲远点别打"）。

§5 风险 2 原文预警过这件事："代价权重写错，MPC 会退化成躲得远远的不打，所以位置偏好与对准项必须一起给"。
**预警写在文档里，实现时没有兑现。** 这是本轮最该记的一条。

修法（最小改动）：把瞄准项从"软惩罚"改成**硬的站位约束**——在安全解集里按"能否打到 boss"
排序，并给它与安全项同阶的量级；同时开局无 boss 的阶段用"屏幕中上"当代理目标，否则那 16% 的帧
标签仍然是纯躲避。

**③ 第 5 层的后半段（PPO 微调）一次没跑。**
§5 风险 3 明确写着"纯模仿 ≤ 老师；M5 必须留 RL 阶段"，而 §9~§11 全部实验都是 BC/DAgger。
所以 678 这个数字的含义要精确：**它是"纯模仿的上限"，不是"M5 的验收结果"**。

### 12.4 对"方向正确性"的判断

**正确的部分（可以继续押注）**

1. **规划器作为能力上限的代理**是被数据坐实的：同环境同弹型，规划器 1200 满、反应式策略在
   `ring_gate`/`wall_gate` 上结构性失败，且只有规划器能上穿（`min_y 44.6`）。"先有强老师再蒸馏"
   这个路线本身没问题。
2. **动作空间比算法更关键**：`focus` 一个动作空间改动（9→18）带来的提升（`aimed_single` 765→1200、
   `dense_ring` 359→770），大于所有蒸馏算法改动之和。**以后先查动作空间，再调损失。**
3. **"并列"是这个问题的核心结构**，不是噪声：换成并列组 CE 后 `rank_acc` 21%→70%、
   且少 50 局就超过回归。这条认识可以迁移到任何"多动作同样安全"的连续控制问题。
4. **学习型动力学的价值只可能在真机兑现**，而它已经被真数据证实（44%）。这是 v2 相对
   "纯规则"路线唯一不可替代的东西。

**需要修正的部分（不改就别再往下堆实验）**

1. **把"老师的目标函数"当第一优先级，而不是蒸馏算子。** 现在的老师是"安全策略"，
   v2 需要的是"通关策略"。修法二选一：
   - 给对准项加量级（例如"能打到 boss 的站位"变成 `−w·1[打不到]`，`w` 与安全项同阶）；
   - 或把代价改成两层：**安全 = 硬约束（死/不死）**，**其余全是软目标（对准、站位、进度）**，
     由软目标在安全解集里排序——这样并列会自然减少，回归也才有连续价值。
2. **先跑 RL 再谈蒸馏上限。** 678 是模仿上限，不是路线上限。用 BC 678 初始化跑 PPO（`multi` 档奖励，
   `progress_scale` 打开），才有资格判断 v2 行不行。
3. **观测规模跟样本量走**：239 维够用，822 维在本样本量下有害。若要用规划器同构观测，
   得同时把样本量提到 10 倍以上，否则不做。

### 12.5 一个战略判断：mock 已经刷不出新信息了

| 事实 | 含义 |
|---|---|
| 老师 = 1200 = bench 上限（`--max-steps 1200`） | mock 上老师已满分，**无法再用它区分"更好的规划"** |
| mock 弹幕全是匀速直线（`§2.3` 自己写的） | **M2 的价值在 mock 上恒为 0**，v2 最独创的一层在这个环境里被结构性取消 |
| 学生 678，且卡在"老师不完整"而不是"蒸馏学不会" | 继续在 mock 上调蒸馏参数，收益上限很低 |
| M5 的任何产出**从未上过真机** | 真机才是唯一能证伪/证实的地方 |

→ **在 mock 上还能做的只剩两件**：① 修老师代价（12.4-1）；② 跑 RL 微调（12.4-2）。
**其余 mock 实验的边际价值已经很低**，再刷分只会得到"更贴一个不完整的老师"。

### 12.6 下一步（按这个顺序，前三步都不需要真机）

1. **修老师代价**（最小改动）：① `aim_weight` 从 0.35 提到与安全项同阶；② 开局无 boss 的阶段
   （占前 ~16%，见 §12.3-②）用"屏幕中上"当代理目标，否则那批标签仍是纯躲避。
   验收：老师自己的**对准率 > 60%**、`aimed_*` 弹型存活不掉；`teacher_check` 的"代价间隙"应显著变大
   （并列减少），这同时给回归路径一个复活的机会。
2. **跑 PPO 微调**：`--load .runtime/rank_focus/policy.npz` + `multi` 奖励 + `progress_scale>0`。
   验收：6 弹型均值 > 678，且对准率不再是个位数。
3. **把动力学接进蒸馏链路**（`TrainConfig.mpc_dynamics` + `mock_full_clear --mpc-dynamics`）。
   mock 上无增益（预期），但为真机 replay 复刻准备。
4. **上真机一次**：跑 `check_focus.py` → 带 focus 的 18 动作策略 × replay 弹幕。
   这是唯一能回答"v2 是否真的强于规则策略"的实验。

> 一句话收束：**方向对，但当前卡点不在算法而在老师的目标函数；而 mock 已经不能再给新答案了。**

## 13. 贴顶治理 + 承诺期按帧 + tie-aware ListMLE（2026-10-22 收尾）

§12 的结论是"卡点在老师的目标函数"。用户给了一个更具体的观察和一组更具体的改法，
这一节逐条实现并量了数。

### 13.1 先厘清一件事：贴顶不是老师教的

原计划是"给老师的代价加位置偏好"。但先测了老师自己到底贴不贴顶
（`.runtime/probe_top.py`，MPC 直跑 900 步，`step_frames=2`）：

| 弹型 | top_w | 存活 | 贴顶占比（y<42） | min_y | 均 y |
|---|---|---|---|---|---|
| ring_gate | 0 | 900（满） | **0.0%** | 354 | 424 |
| ring_gate | 1.5 | 900（满） | 0.0% | 347 | 423 |
| ring_gate | 3.0 | 900（满） | 0.0% | 354 | 424 |
| dense_ring | 任意 | 900（满） | 0.0% | 334 | 429 |

**老师从不贴顶**（min_y 334~354，全程在屏幕下半部），而 §11 的学生 `ring_focus`
在同一弹型上贴顶 **29%**、min_y **8**。

→ 结论反过来了：**贴顶是学生模仿时的自发退化，不是老师示范的**。
可能的原因是学生只看到最近 32 颗弹——往上躲能同时"减少可见弹量"和"远离危险"，
于是它把"上穿"这个**局部手段**当成了**长期策略**。

这决定了改法的重心：位置偏好加在老师那边**几乎无效**（老师本来就不贴），
真正起作用的是**学生侧的位置正则**（13.4）。

### 13.2 代价函数的位置偏好（保留，作为上穿时的租金）

`mpc.py` 新增三组"持续贴边"惩罚（`top/bottom/edge_weight` + 各自 margin）：

```
zone = w_top · max(0, top_margin − y)²                      # 逐步算, 不只看终点
     + w_bottom · max(0, y − (H − bottom_margin))²
     + w_edge · (max(0, edge_margin − x)² + max(0, x − (W − edge_margin))²)
cost += zone.mean(axis=1)                                    # 平均, 与视界长度无关
```

三个设计点：

* **逐步平均**而不是只看终点：§10 的 `y_weight` 只罚终点站位（量级 ≤2.1，被安全项
  200~800 淹没），拦不住"先上去躲一堵墙、然后整段贴着"。取 mean 让代价与视界长度无关，
  长短视界可比。
* **二次**：让"贴 5px"和"贴 30px"有明显区别（线性项在大代价面前等于常数）。
* **允许上去**：只有 y < `top_margin` 才计费，且是"租金"不是"禁止"。
  实测 `top_w=1` 就能把"继续向上"的代价从 1.3 推到 769（与碰撞项同阶），
  而短暂上穿只占视界的一小段，mean 很小。

### 13.3 承诺期改成按帧（8~15 帧）

`MPCTeacher.commit_frames`：按**游戏帧**给，内部 `commit_steps = round(frames / step_frames)`。
`step_frames=2` 时 8/12/15 帧 = 4/6/8 个决策步。承诺期一结束（`_commit_left` 归零），
下一次 `choose` 即重新规划并自由换向 —— 也就是"每个承诺期结束后重新规划"。

> 为什么不用更长的承诺：承诺本身是"用响应性换稳定性"。§10.2 实测 `commit_steps=3`
> 把换向率从 51.8% 压到 27.2%，但 `aimed_single` 的对准率也从 52% 掉到 42%
> （"转向对准"的收益小于 `switch_margin`）。所以承诺期是有代价的，
> 8~15 帧是"够稳、又不至于锁死一个错方向"的区间。

### 13.4 蒸馏改成 tie-aware ListMLE（`MLPPolicy.fit_listmle`）

**先做了候选动作采样**：每个状态随机取 K 个动作（必含 argmin），其余不参与 loss。
`--rank-candidates 0` = 用全部动作。采样既省算力，也让每轮覆盖不同负例。

**loss 按组连乘，组内不连乘**：

```
groups: 把候选按代价排序, 相邻差 ≤ margin 归为同组
P      = ∏_g  (Σ_{i∈g} e^{s_i}) / (Σ_{j∈g及其后} e^{s_j})
loss   = −Σ_g [ LSE(s_g) − LSE(s_{g 之后所有组}) ]
```

相对 §11 的"并列组 CE"，多用了**组外的完整次序**（CE 只知道"谁在最优组里"，
listwise 还知道"次优 > 差"）。两个边界都对：全并列时只剩一组，
`LSE(全) − LSE(全) = 0`，loss 与梯度双零；无并列时退化成标准 ListMLE。

**坑：loss 对称 ≠ 梯度对称。** 写完先做了数值对拍（解析梯度 vs 中心差分，
最大误差 4.6e-10），以为对了；但再测"并列组内 logits 是否被拉开"，发现
**并列的两个动作梯度差 35 倍** —— 因为 `∂loss/∂s_t ∝ e^{s_t}` 仍带着各自的分数。
这和 §11.2 的成对 RankNet 是同一个坑，只是换了个位置出现。

修法：**组内梯度均摊**（把整组当一个决策单元，总推力守恒
`Σ_t 均值 = Σ_t grad_naive`，组内每个元素拿到的梯度完全相同）。
修完并列组内 |Δlogit| 从 1.1 量级降到 **0.23**，而"最优组 vs 次优"仍有 4.6 的间隔。

**另一个实测约束**：ListMLE 的稳定学习率上限比 `fit_rank` 低。

| lr | 100 步 | 200 | 300 | 400 | 500 |
|---|---|---|---|---|---|
| 3e-4 | 0.59 | 0.76 | 0.86 | 0.92 | 0.95 |
| **1e-3** | 0.84 | 0.98 | **1.00** | 1.00 | 1.00 |
| 2e-3 | 0.95 | 1.00 | 1.00 | **0.88** | 0.77 |

2e-3 会过冲、后期退化（logits 无界增长破坏排序）。**建议 lr ≤ 1e-3**。

### 13.5 学生侧位置正则：先做单向，失败了

`_position_reg` 是纯几何的正则，只看自机位置、不看观测：
贴顶时给"继续向上"的动作一个正权重（越贴越重），损失加 `w·Σ_a p_a·reg_a`
（负权重 = 奖励，见下一节）。

70 局消融（同配置，只差这一项）：

| 配置 | 6 弹型均值 | 平均贴顶 | ring_gate | aimed_single | 备注 |
|---|---|---|---|---|---|
| 无正则 | 442 | **0%** | 385 | 597 | 从不上穿，min_y ~400 |
| 单向正则（w=2） | **504** | **21%** | **1200（贴顶 78%）** | 535 | 学会上穿了，但贴上就不下来 |

判读：单向正则**成功让学生学会上穿**（`ring_gate` 385 → 1200 满），
但没有给它"下来"的理由 —— **"不往上"≠"往下"**：在顶部时"停住/横移"同样不产生惩罚，
于是最省事的选择就是继续贴着（78%）。这就是 13.6 的修法。

### 13.6 双向正则（回中场吸引）

给"往回走"**负权重**（乘 `p_a` 后等于奖励），形成"贴顶 → 回中场"的闭环。
`position_reg_pull=0.8` 表示"回中场的奖励"是"别再往外的惩罚"的 0.8 倍。
权重同时从 2.0 降到 1.0（单向版让 loss 从 9 涨到 25，说明正则占了主导）。

> 结果见 §13.7。

### 13.8 判读：贴顶和对准都有解，但都收"存活税"

1. **贴顶是可以彻底压掉的**（9% → 0%），代价是存活 **−37%~−50%**。
   原因很直接：**贴顶本身是一种逃课**——越往上弹幕密度越低，屏幕下方反而更危险。
   把自机拉回中场，等于主动走进密集区。这不是实现 bug，是任务的真实结构。
   反过来说：**§11 那个 678 里有 9% 的帧是靠贴顶换来的**，但它不是主要得分来源
   （主要来自 `dense_ring` 771 / `closing_ring` 659，这两个弹型贴顶只有 0%/19%）。
2. **对准率可以提升 5 倍**（7% → 32~34%），这一项是干净的正收益：位置正则把自机
   拉回中场，正好落在能打到 Boss 的列上。单看"打法是否正确"，双向版明显更好。
3. **单向正则是个陷阱**：它让学生**学会上穿**（`ring_gate` 385 → 1200 满），
   但因为没有"下来"的力，`ring_gate` 变成 78% 时间挂在天花板上——
   分数最高、行为最差。**这类"分数涨了但行为退化"的改动必须用贴顶指标才看得出来**，
   这也说明本轮加的 `top_ratio`/`min_y` 诊断是必要的（之前所有评测都没法发现它）。
4. **温和档（w0.5/p0.4）是当前最平衡的一档**：429 分（−37%）、0% 贴顶、32% 对准、
   `aimed_single` 满 1200。它比重量档多活了 90 步，说明正则在 w≈0.5 附近还没有
   把躲避能力压坏。
5. **ListMLE 本身没有超过 §11 的 rank CE**（同为无正则口径：442 vs 583 的旧记录）。
   但要注意 §11 的 583 是 9 动作、这次是 18 动作（含 focus），口径不同；
   在同为 18 动作、有正则的条件下，ListMLE 的行为质量（对准、贴顶）明显更好。

## 14. 温和档拉到 200 局：续训有效、从零无效（2026-10-22 末）

§13.9 的第一条建议是"把温和档拉到 200+ 局"。这一节做了两个版本，顺便回答了
§11.5 留下的那个疑问（"续训会不会反而更差"）。

### 14.3 三条判读

1. **续训有效，从零无效。** 429 → **463**（+8%），而从零 200 局反而掉到 397 < 429。
   同一个配置、同样的总数据量，差别只在"是否从已收敛的权重出发"。
   合理解释：ListMLE 对 lr 敏感（§13.4 实测 2e-3 会后期退化），
   从零跑 200 局等于让 Adam 在同一个 lr 下跑更久，后期在漂移；
   续训相当于**从收敛点再走一段**，更像退火。这也修正了 §11.5 那条
   "续训不涨"的结论 —— **续训本身不是问题，lr 与起点才是**。
2. **最有价值的不是分数，是伤害：246 → 442（1.8 倍），对准 7% → 35%（5 倍）。**
   续训版是真的在"打"：`wall_gate` 241 → 408、`closing_ring` 331 → 466
   都是长视界弹型，说明学到的是"边躲边打"，而不只是苟活。
   贴顶只有 2%（基线 9%），且不再是"挂在天花板上"那种。
3. **分数仍低于基线 678，但要看清那 678 是什么**：贴顶 9%、对准 7%、伤害 246。
   基线主要靠 `dense_ring`(771)/`ring_gate`(808) 两个"躲着不动"的弹型撑起来，
   而这两个弹型正是续训版最弱的（236/292）。**这是同一个权衡的另一面**：
   想在中场打，就得吃密集弹幕。

### 14.4 承诺期 8/12/15 帧的对照（补 §13.9 第三项）

`tools/teacher_check.py --mpc-commit-frames`（`ring_gate`，100 帧，`step_frames=2`）：

| 承诺期（帧） | 决策步 | 换向率 | 标签换向 | **动作 ≈ argmin** |
|---|---|---|---|---|
| 0 | 0 | 51.5% | 51.5% | **100%** |
| 8 | 4 | 23.2% | 51.5% | 73% |
| 12 | 6 | 19.2% | 51.5% | 61% |
| 15 | 8 | 17.2% | 51.5% | 67% |
| 24 | 12 | **13.1%** | 51.5% | **49%** |

**换向率随承诺期单调下降，但"动作 ≈ 当前帧代价的 argmin"也单调下降**——
因为承诺期里老师执行的是**上一个承诺的方向**，而代价向量每帧都在重算。
24 帧时只剩 49% 一致：**一半的帧，老师给的标签在说"该往 A"，而老师自己在走 B**。

这解释了为什么承诺期不能一味加长，也提示了两条改法（未做）：

* 承诺期内**冻结代价标签**（让标签也承诺），标签与动作才能重新对齐；
* 或者干脆放弃"每帧重新算代价 + 承诺压制"的组合，改成"承诺期内只标一次，之后 N 帧复制该标签"。

按这张表，**8~12 帧是平衡点**（换向率 19~23%、标签错位 27~39%）。
本轮实验统一用 12 帧。

## 15. PPO 微调：第一次跑通"RL 那半层"（2026-10-23）

§12.3-③ 指出 M5 只做了 BC/DAgger，"蒸馏后用 RL 微调"这半层**从未运行过**，
所以 678 那个数字是"模仿上限"而不是路线结论。这一节把这一层补上：以 §14 的
`lm200_cont` 为 BC 初始化跑 PPO。

### 15.1 做法

链路本来就是通的（`trainer._update_ppo`：GAE + clipped surrogate + `_value_scale`
把价值回归压到 O(1) + 可选的 KL 锚），只要**不设老师**就自动进入 PPO 分支：

```bash
python tools/mock_full_clear.py \
  --load .runtime/lm200_cont/policy.npz \
  --algorithm ppo --reward-profile multi \
  --lr 3e-5 --batch 8 --ppo-minibatch 512 --ppo-epochs 4 \
  --episodes 600 --max-steps 900 --step-frames 2 --k-bullets 32 --danger-grad \
  --pattern-cycle aimed_single,aimed_spread,dense_ring,ring_gate,closing_ring,wall_gate \
  --out .runtime/ppo_cont
```

三个细节值得记：

* `--load` 之后 `apply_hyperparams()` 会用**本次命令行**的 lr / entropy 覆盖 checkpoint
  自带的值。这是个曾经很贵的 bug（"命令行写 3e-5、实际按 1e-3 跑"，让所有 PPO 微调
  都以 10~30 倍学习率把 DAgger 策略打崩），已在 §代码里修掉。
* `kl_anchor > 0` 且无老师时，`start()` 会**冻结参考策略**（`_capture_rl_reference`），
  否则 KL 锚静默失效。
* 训练用的奖励是 `multi` 档（`progress_scale=6`、`position_scale=0.5`、
  `position_y_target=0.85`），不是蒸馏时的 posreg —— 两者的语义完全不同。

### 15.2 结果（同口径：6 弹型 × 5 seeds 贪心，1200 步上限）

| 配置 | 起点 | lr | 局数 | **均值存活** | **对准** | **伤害** | 贴顶 |
|---|---|---|---|---|---|---|---|
| BC 基线 `lm200_cont` | — | — | — | 463 | 35% | 442 | 2% |
| PPO + KL 锚 0.05 | BC | 1e-4 | 600 | 508 | 30% | 460 | 0% |
| PPO 无锚 | BC | 1e-4 | 600 | 740 | 21% | 502 | 0% |
| PPO 无锚（长跑） | BC | 1e-4 | 2000 | 786 | 14% | **219** | 0% |
| PPO 小 lr 直接跑 | BC | 3e-5 | 600 | 674 | 16% | 345 | 0% |
| **PPO 续训（最好）** | a00(600) | 3e-5 | +1500（快照@+600） | **902** | 14% | **558** | 0% |
| PPO 再续一轮 | cont | 3e-5 | +1500 | 842 | 7% | 277 | 0% |
| PPO `multi_attack` | BC | 1e-4 | 800 | 692 | 14% | 218 | 0% |

分弹型（最能说明问题的是两端）：

| 弹型 | BC 基线 | PPO 无锚 600 | **PPO 续训** | PPO 长跑 2000 |
|---|---|---|---|---|
| aimed_single | 1115 | 1200 | 1200 | 1200 |

### 15.3 判读

1. **PPO 微调确实有效，而且是这一轮唯一"翻倍级"的改进**：463 → **902（+95%）**，
   伤害 442 → **558（+26%）**，贴顶仍是 0%。§12 里"必须跑 RL 才有资格判断 v2"
   这一步现在有了第一个正面答案。
2. **`dense_ring` 与 `closing_ring` 是主要受益者**（236→1200、466→930），这两个都是
   "持续密集弹幕"型 —— 正是模仿学不到、必须靠奖励优化的那类。这印证了 §14.3 的
   "学生学会了打、没学会躲"。
3. **对准率下降不是退化**：35% → 14%，但伤害上升。因为对准率是"每一步的比例"，
   而伤害是累计量；活 902 步 × 14% 的累计输出，大于活 463 步 × 35%。
   评测时**必须同时看两个指标**，只看对准率会得出完全相反的结论。
4. **KL 锚是负担，不是安全带**：锚 0.05 时只有 508，无锚 740。原因是 BC 策略本身
   不够好（463），把 PPO 拴在它附近的收益上限就是"BC 水平"。这条与直觉相反，
   值得单独记住：**KL 锚适合"防崩"，不适合"求改进"。**
5. **必须早停**：`ppo_cont` 的最佳快照出现在 **+600 局**，之后每一步评估都在退化
   （ep800 伤害 163、ep1201 掉到 114）。再续一轮 1500 局，存活 902 → 842、
   伤害 558 → 277。**PPO 在 mock 上的有效窗口大约 600~800 局，之后开始"苟化"。**
6. **`multi_attack` 的配平改动失败了**（692 / 218）。见 15.4 —— 不是方向错，是改过头。

### 15.4 "越训越苟"的机制：输出与存活差 30 倍

把 `multi` 档的量级摊开算一局：

```
存活:  alive_bonus 0.3 × 600 步            ≈ 180 分
输出:  progress_scale 6.0 × Δ血量比(0~1)   ≤   6 分
       boss_damage_scale 0.1 × 500 点伤害  ≈  50 分
```

**输出 : 存活 ≈ 1 : 3 ~ 1 : 30**。PPO 优化这个奖励，等价于优化"别死"，
苟化不是 bug 而是设计的结果。这条在训练日志里看得很直白：
`伤害(均)` 从 500 一路滑到 105，而 `存活步数` 一路涨到 686。

据此加了 `multi_attack` 档（`progress 60` / `boss_damage 0.3` / `alive 0.1`），
把两者拉到同一量级。**结果更差（692 / 218）**，说明这个改法错在两处：

* **一次改了三个权重**，无法归因；`alive 0.3 → 0.1` 同时也削弱了"活下去"的信号，
  而存活恰恰是当前最该保的；
* **即时奖励被放大 10 倍**（progress 6→60、damage 0.1→0.3），相对稀疏的长期回报
  被淹没，策略退化成"追着 boss 打"，反而死得更早。

正确做法应该是**只动一个**（例如只把 `progress_scale` 提到 30、其余不变），
且用同样的 600 局 / lr 1e-4 口径对照 —— 本节没做，留给下一步。

### 15.5 现状

| 项 | 结果 |
|---|---|
| **当前最强策略** | `.runtime/ppo_cont/policy_best.npz` —— **902 步 / 伤害 558 / 贴顶 0%** |
| 相对 BC 基线 | 存活 **×1.95**、伤害 **×1.26**、贴顶 2%→0% |
| 相对 MPC 老师（1200 满 / 479） | 存活 75%、伤害 **116%**（学生打出的伤害已超老师） |

| 样例 | `.runtime/demo_ppo/demo_ep1.gif`（`dense_ring` 1200 步跑满、2 残） |

`lm200_cont → ppo_cont` 这条链是目前 v2 的**最好结果**：从蒸馏（§13~14）拿到
"会打"的策略，再用 PPO 补上"能躲"的一半，伤害超过老师、存活到老师的 3/4。

下一步（按性价比）：

1. **早停 + 多快照**：`best` 现在按 `mean_ret` 选，会把"苟活快照"当成更优。
   应改成 `(存活, 伤害)` 联合（如 `存活 × 0.7 + 伤害 × 0.3` 归一化），
   并在每 100 局存一次快照，事后按 pattern_bench 选。
2. **奖励只动一个旋钮**：`progress_scale` 6→30（其余不动），600 局 / lr 1e-4，
   与 740 那组同口径对照。这次不要一次改三个。
3. **`wall_gate` 单独处理**：它的失败与 §11 的缺口观测同源 —— 墙需要"提前 60 帧
   横向占位"，反应式策略 + 即时奖励给不出这个信号。要么给"墙型"单独配奖励，
   要么在这一类弹型上保留规划器（hier 老师）。
4. 真机验证：`tools/check_focus.py` → 这条链（18 动作、含 focus）直接可跑。

## 16. 专攻"躲避"的两条路都失败了 —— wall_gate 是结构问题（2026-10-23）

§15.5 的下一步里排了"专攻弱项"。用户也明确要求"先放下对准率、着重练躲避"。
这一节把两条最直接的路各测了一遍，**结论是：继续训练和补特征都解决不了 `wall_gate`**。

### 16.1 弱项加权采样

把 `--pattern-cycle` 改成 `wall_gate,wall_gate,wall_gate,aimed_spread,aimed_spread,
closing_ring,aimed_single,dense_ring,ring_gate`（`_apply_pattern` 是 `cycle[index % len]`，
重复项即加权），从 `ppo_cont`（902）起续训 600 局、lr 3e-5：

| | BC 基线 | ppo_cont（起点） | 弱项加权 600 局 |
|---|---|---|---|
| 均值 | 463 | **902** | 738 |
| `wall_gate` | 408 | 328 | **279** |
| `aimed_spread` | 264 | 554 | 521 |
| 伤害 | 442 | 558 | 279 |
| 对准 | 35% | 14% | 6% |

**加权 30% 的 `wall_gate` 反而更差（328→279）**，而且整体退化。原因不是"采样不够"，
而是**继续训练本身在退化**（§15.3-⑤）：600 局里策略先苟化，加权只是让它更快地
学会"在墙面前不动"这种最省事的解。

### 16.2 墙特征扩维

`features.py` 里已有 12 维墙特征（覆盖率 / 缺口中心偏移 / 缺口宽度 / 到达 ETA /
8 列带占用），且支持 `--expand-input` 零初始化扩维。从 `ppo_cont` 起：

```bash
python tools/mock_full_clear.py --load .runtime/ppo_cont/policy_best.npz \
  --wall-feat --expand-input --algorithm ppo --reward-profile multi \
  --lr 3e-5 --episodes 600 ...
```

扩维成功（`obs_dim` 239 → 251、参数 +3072），训练 600 局后：

| | ppo_cont | 墙特征 600 局 |
|---|---|---|
| 均值 | 902 | 759 |
| `wall_gate` | 328 | **290** |
| 伤害 | 558 | 189 |

**权重确实长起来了**（输入层最后 12 行的列范数均值 **2.07**，与其它列 **2.03** 相当，
说明不是"零初始化后没学动"），但成绩不变。

### 16.3 判读：这不是信息问题，是提前量问题

三条证据合起来指向同一个结论：

| 证据 | 说明 |
|---|---|
| 加特征后权重非零但成绩不变 | **信息不缺**，策略能"看到"缺口和 ETA |
| 加权采样无效、续训更差 | **不是采样分布问题** |
| 规划器（72 帧视界）同弹型 1150~1200 | **需要提前约 70 帧的决策** |

算一下就清楚：缺口可能在 300px 外，玩家速度 4.4px/帧（`step_frames=2` 时 8.8px/步），
横向过去要 **~34~68 帧**。反应式策略每帧只看到"当前 + 最近 32 颗弹"，它必须
**在没有记忆的情况下，从单帧的 ETA 和缺口偏移里推出"现在就得动"** —— 这在原理上
做得到（ETA 特征已经给了），但在"600 局 PPO + 一个正在苟化的策略"里学不出来。

所以本轮把这条线**定为结构问题**，不再用反应式策略硬啃：

* `wall_gate` 交给分层规划器（`hierarchical`，历史实测 814→2000）；
* 反应式策略专心做"持续弹幕"类，那里它已经打满三个弹型。

### 16.4 这一轮真正学到的东西

1. **"继续训"不是万能药**：从峰值快照出发的**四组**续训（再续一轮 842、加权弱项 738、
   墙特征 759、大步长长跑 786）**全部低于 902**。这个任务上，PPO 的有效窗口就是
   600~800 局，超过就漂。
2. **补观测要先确认"是缺信息还是缺提前量"**：两者的修法完全不同。判断方法很便宜 ——
   看新特征列的权重范数（长起来了 = 不是缺信息）+ 看规划器在同一弹型上的成绩
   （很高 = 缺提前量）。
3. **加权采样会放大退化的方向**：它不能"补短板"，只能让策略更快地收敛到当前奖励
   下的最省事解。要补短板得改奖励或改结构。
