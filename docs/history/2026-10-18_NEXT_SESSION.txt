【1. 本轮确认的根因 (最重要)】
------------------------------------------------------------------------
机制 (mock 侧代码可完整复现, 真机同理):
  a) `backends/mock.py::_hit()`: 被弹时把自机 **瞬移** 回 (192, 416), 并给
     `INVINCIBLE_FRAMES=150` (2.5 秒无敌);
  b) `_hit()` 同时清掉自机周围 60px 内的弹幕 -> **弹幕空窗**;
  c) 奖励里 `boss_damage_scale` 很高(工具里 1.0) -> 无敌期内"零风险"持续输出;
  d) `miss_penalty` 只有 -30 (掉一残才 -30), `death_penalty` -100 ~ -150;
     => 一次掉残换来 2.5 秒安全输出, **对策略是划算的**。

结果: 动作分布长期以 `shoot`(站桩) 为主(52%~70%); 贪心评估最远只到 **第 2 面**;
      demo 里 168 步就通关第 1 面、随后在第 2 面被秒。
即: **它优化的是"被打之后的反击", 不是"不被弹"。**

结论: 这是**奖励设计漏洞(激励被弹)** + **观测缺失(看不到无敌帧/危险提前量)**,
      不是单纯的训练量问题。

【5. replay 方案可行性 (已确认, 但注意关键事实)】
------------------------------------------------------------------------
事实: 东方的 `.rpy` **只存 随机种子 + 每帧输入**, **不存敌机/弹幕位置**;
      回放是游戏用它自己确定性重演。所以:
  x 不能"从 replay 解析出弹幕轨迹"
  v 可行且推荐的做法:
     1) 解析 .rpy 的逐帧输入(th11 格式, 可参考 thtk 等社区工具);
     2) 让游戏回放(游戏自带 replay 播放器最稳, 帧锁定; 或用 SendInput 逐帧喂入);
     3) 用我们的实体读取器, 以 `frame`(0xA5734) 计数**每帧读一次状态**;
     4) 得到 `(真实状态, 人类动作)` 数据集 -> 行为克隆 / 离线 RL。
  前提/成本: replay 与游戏版本必须一致(F 盘 1.00a ✓);
            每帧读 ~4.6MB(约 1~3ms), 60Hz 可行;
            .rpy 解析需要按 th11 规范写(或用现成工具转成帧输入表)。
  结论: "把 replay 变成模拟器" 不行; "把 replay 变成真实数据来训练" 可行,
        是缩小 sim-to-real 的正路。

【6. 已知坑 (务必避免重复踩)】
------------------------------------------------------------------------
1) ★不要把 PowerShell 的 `Get-Content ... | Set-Content ...` 用于改源码:
   它会把 UTF-8 文件写坏(换行重复 + 中文变 U+FFFD + 代码行被并进注释)。
   本项目已被此坑弄坏过 trainer.py(已修复)。改文件请用编辑工具或 Python 写。
2) `env.get_state()` 不推进帧: 用它的 state 取 `bullet_velocity` 会全是 0;
   必须用 `env.step()` 返回的 state。
3) `clip` 会裁掉单步大奖励(过面/通关奖励落在一步) —— 见 A7。
4) `config.json` 与各 tools 里的 REWARD 目前不一致 —— 见 A6。
5) mock ≠ 真机: 弹型/关卡脚本/难度曲线完全不同, mock 通关不代表真机。
6) 真机 `restart_process=True` 会**每局重启游戏**(约 60s 开销);
   `--max-steps 0` 才是"只在死亡/通关时结束"。
7) 真机 `invincible`/`bombs` 未标定; 放弹只扣 power(无独立计数)。
8) CE 的 autorun 脚本用完必须删(`E:\Cheat Engine\autorun\zz_*.lua`)。
9) 真机标定期必须锁血, 否则被弹瞬移会污染标定/试验。
10) `th11.json` 的 Rank Select 是循环列表: 默认 Normal, 按 1 次"上"=Easy。
