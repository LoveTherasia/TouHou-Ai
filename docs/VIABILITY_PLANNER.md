# 可行域规划器：终于有一个能过 `wall_gate` 的东西

> 2026-10-21。代码 `touhou_rl_mcp/training/viability.py`，工具
> `tools/pattern_bench.py --policy planner`。
> 结论先行：**8 种弹型平均 1970/2000 步**（学习策略 1852），`wall_gate` 从
> **814 → 2000 步**——这是项目里第一个能在 `wall_gate` 上活满窗口的东西。

## 0. 为什么把旧的 `MacroPlanner` 重写

旧实现（`training/planner.py`，保留未删）在 120 帧上做 beam search，排序键是
**"违规帧数 + 最大化最坏间隙（20px 封顶）"**，再用终局"活路数"打破平局。

问题：`maximin` 间隙在密集弹幕里等价于**"往最空的地方跑"**，而"最空"永远是角落；
它分不清"站在缺口里"和"站在场地另一端"。更根本的是它从来没有回答一个问题：

> **从现在这个位置出发，还有没有一条能活到 T 帧之后的路？**

这是一个**全局可行性**问题，靠"对单条路径打分"搜不出来，必须把整张网格的时间展开
算一遍。

## 1. 做法

1. **网格对齐真实运动**：`cell = speed*dt/2`（dt=2 → 4.4px），于是轴向 = 2 格、
   斜向 = (1,1) 格，与真实位移**精确相等**（斜向略慢，是"保守"而非"冒进"）；
2. **危险场**：把每颗弹按速度外推到 horizon 的每一帧，栅格化成硬危险区与缓冲带；
3. **反向 DP**：
   `C[k] = 死亡? (DEATH + 剩余层数) : 缓冲带代价 + min_{9 方向} C[k+1][p+move]`；
4. **掷第一步**：`argmin_delta C[1][p0+delta]`，每帧重规划。

因为 `C` 里已经含"未来所有层"，150 帧后才压到自机高度的墙会自动体现出来 ——
**不需要任何"墙"的特判**。

默认参数：`horizon=180, dt=2, kill_radius=5, hard_buffer=2, lead_frames=20,
soft_weight=0.05, aim_weight=0`。

## 2. 踩过的四个坑（都是"看起来能跑、其实在送死"）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 想往左却按了上 | `(d_col, d_row)` 写成了 `(uy, ux)`，**方向转置**；DP 按错的几何算，动作名按对的发 | 用 `DIRECTIONS` 直接映射，并加"轴向必须精确、斜向不许更快"的单测 |
| 2 | 一直原地不动 | 危险场用 `(1-d/r)²` 且 `r=5px`、格子 6.6px，**一颗正压在身上**的弹只值 0.26 代价 —— 被打中几乎免费 | 硬危险区（命中=1.0），半径 `5px + 半格对角 + 2px` 吃掉量化误差 |
| 3 | 会主动往墙上撞 | 代价是"危险层数之和"，于是**早死比晚死便宜**（2 层 < 18 层） | 死亡改成**一次性终止代价** `DEATH + (层总数-当前层)`，越晚死越便宜 |
| 4 | 一堵 100px 外的墙就让全场"必死" | 时间影子（提前 20 帧标危险）被当成了硬危险 | 影子只做**软代价**（提前站位的压力），硬危险只认"此刻真的被覆盖" |

第 2、3、4 条合起来的效果：`wall_gate` 从 543 → **1100** → **2000**。

另外一条经验：缓冲带（soft）**只能比硬区多 1 格**。多 2 格以上时，48px 的缺口在
6.6px 网格上会被糊成 1 格宽，规划器就分不出"缺口中间"和"贴着子弹走"了。

## 3. 结果（`pattern_bench`，上限 2000 步，2 个种子）

| 弹型 | 规划器（纯躲避） | **规划器 + 对准 0.15** | `attack_ppo_fixed` |
|---|---|---|---|
| aimed_single | 2000 / 4% | **2000 / 92%** | 2000 / 96% |
| aimed_spread | 2000 / 9% | 1770 (1 死) / 63% | 2000 / 93% |
| fan | 2000 / 0% | 2000 / 87% | 2000 / 91% |
| spiral | 2000 / 2% | 2000 / 61% | 2000 / 96% |
| dense_ring | 2000 / 0% | 2000 / 79% | 2000 / 90% |
| ring_gate | 2000 / 2% | 2000 / 83% | 2000 / 95% |
| closing_ring | **700 (2/2 死)** | 1990 (1 死) / 73% | 2000 / 76% |
| **wall_gate** | 2000 / 20% | **2000 / 43%** | **814** / 97% |
| **平均存活** | 1838 | **1970 (98%)** | 1852 (93%) |

（格式：存活步 / 对准率；上限 2000，所以"2000"= 打满窗口）

三个可以直接写进结论的事实：

1. **`wall_gate` 解决了**：814 → 2000。而五个老师亲自打只有 546~914，
   学习策略全部死在 662~814 —— 说明这从来不是"训练不够"，是**没有前瞻**。
2. **`aim_weight=0.15` 让"能活"变成"能活且能打"**：对准从 0~20% 提到 61~92%，
   存活不掉。它的含义很直白：在所有**同样安全**的位置里，挑离 Boss 那一列最近的。
3. **规划器不是全面更强**：`aimed_spread` 有空局死亡（1770、1/2），
   `closing_ring` 纯躲避时 700 步就死 —— 这两类是"多方向同时收网"，软代价 0.05
   提供的"舒服度"梯度在几个方向同时逼近时不够用。

## 4. 代价：慢

每次决策 **25~40ms**（87×101 网格、90 层、9 方向 DP，纯 numpy）。
2000 步一局约 60~80 秒，**不能**在真机 60fps 上闭环。所以它现在的定位是：

* **验收基准**（"这条命本来能不能活"的参照）；
* **老师 / 示范来源**（`--teacher viability`，配合 `--planner-dt 4` 可降到 ~7ms）；
* 将来做"风险检测 → 只在墙类弹幕上接管"的分层控制。

## 5. 下一步

1. **分层切换**：常规弹型用策略（对准 90%+，比规划器高），检测到"整行弹幕/墙"
   时切到规划器。这是把两边优点合起来的正路。
2. **蒸馏规划器的 wall 片段**：只在 `wall_gate` 场景里用规划器打标签（`dt=4`），
   与通才策略做 DAgger —— 比混合蒸馏靠谱，因为标签只在需要的地方生效。
3. `closing_ring` / `aimed_spread` 的空局：把软代价从"固定 0.05"改成随"可选方向数"
   自适应（收网时提高权重），或对"所有方向都 <阈值"的状态直接触发保命模式。
4. 提速：把 DP 内循环换成 numba/C，或把网格在非墙场景降回 `dt=4`。
