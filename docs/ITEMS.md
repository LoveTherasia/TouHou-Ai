# 掉落物（道具）偏移标定：2026-10-21 尝试记录

> **状态：现行（负结果记录）**。道具偏移**未找到**，已排除的范围不要重复试。

目标是给 P 点 / 点道具 / 星道具这类**掉落物**找到内存布局，好让策略学会"去捡"。
结论先说：**这一轮没找到**，但把"不是哪儿"都测清楚了，并留下可复现的探测工具
`tools/find_items.py`。

## 已有的信号（不需要道具坐标也够用）

- `power`（`0xA56E8`，内存值 ÷20）、`score`（`0xA56E4`，×10）、`graze`（`0xA5754`）
  都已标定，奖励模型已经在用它们（`reward.power_scale` / `score_scale` / `graze_scale`）。
- 所以"捡道具"这件事，训练信号本来就有；缺的只是**去哪捡**（道具的位置）。

## 这一轮试过的四种找法

工具：`python tools/find_items.py <globals|watchall|diff|pool|countdiff|dump>`
（每个子命令都会重启游戏进第一面，边打边采；`LivesLock` 防止中途 game over）

### 1. 管理器指针区扫描（`globals` / `watchall`）

TH11 的全局指针是成块摆放的：弹幕 `0xA8D68`、符卡 `0xA8D6C`、敌人 `0xA8D7C`。
扫 `0xA8A00..0xA9300` 得到 36 个"像指针"的槽，对每个槽指向的对象采样
`+0x00..+0x200` 的 u32（18~20 秒，8Hz），只留下"恒 ≤64 且至少取过 3 个不同值"的字段：

| 槽 | 字段 | 观测 | 判断 |
|---|---|---|---|
| `0xA8D68` | `+0x5C` | 0..45，17 个不同值 | 弹幕活动数（已知） |
| `0xA8D7C` | `+0x70` | 2..13 | 敌人数（已知） |
| `0xA8D7C` | `+0x10` | 0..2 | 与 Boss/阶段有关 |
| `0xA8E90` | `+0x70/+0x74` | (3,4)→(14,15)→(25,26) | 成对同步变化，是坐标/动画，不是计数 |
| `0xA8EB4` | `+0x70/+0x74` | (4,5)→(39,40) | 同上 |

**没有**任何"0..40 之间随道具抖动"的计数 —— 道具池的管理器指针**不在这块全局区**。

### 2. 全堆 float 差分（`diff`）

逐区域"读 A → 50ms → 读 B"，找 `x 不变、y 匀速增加 0.3~8px、都在场地内` 的地址。
命中 3 个，全在 `0x1034A0C0..0x1034A590`，步长 `0x478`，`dy` 全等于 6.00 ——
这是**弹幕池里的慢速直落弹**（弹幕池 = `read_u32(base+0xA8D68) + 0x64`，2000×0x910）。
道具落地/被吸走只要一两秒，等扫完一整遍（217 个区域）早就没了。

### 3. 结构法找池子（`pool`）

假设"道具池是固定步长数组，一死一波就同时掉 3~8 个、位置几乎重合"，
枚举 29 种步长 × 前 400 个场地坐标种子，要求"有效槽 ≥4 且 y 跨度 <90"。
结果 20577 个候选 —— 零值块、常量块全部通过。**没有步长先验时，这个判据不成立**：
弹幕墙同样"一堆 y 相近的场地坐标"。

### 4. 有/无道具的堆块计数差（`countdiff`）

安静期 vs 打死一波后，统计每个堆块里"相邻两个 float 都在场地内"的数量差：

| 堆块 | 大小 | 增量 |
|---|---|---|
| `0x06A67000` | 0x80000 | **+5527** |
| `0x0D86A000` | 0x7BE000 | +1484 |
| `0x02C00000` | 0xD8000 | +79 |
| 其余 | — | ≤ +6 |

增量全被弹幕占满（打一波的同时也打出了几百颗弹）。道具最多几十个，信号被淹没。

## 下一步（可执行的唯一路线）

道具池没有独立的全局指针，说明它挂在某个管理器对象里面（二层指针）。可行的做法是
**反汇编找代码引用**，而不是继续全内存扫描：

1. 已知入口：`0x40AF9A` 读弹幕管理器（`mov ecx,[0xA8D68]; add ecx,0x64`）、
   `0x410540` 返回敌人链表头。道具的生成代码一定在"敌人死亡/掉道具"分支里。
2. 在 `.text` 里搜"`mov reg, [imm32]` 且 imm32 ∈ `.data`"，把读到的全局逐一挂上
   `watchall` 验证（看是否有 0..40 的计数）。
3. 找到池子后再用 `dump` 定位槽内 `position` 偏移（敌人的写法是 `+0x1070`，
   弹幕是 `+0x43C`，道具大概率是另一套），最后按 `games/offsets/th11.json`
   的格式写进去、补签名校验和测试。

在此之前**不要**给策略加"捡道具"的观测：位置不可读时补零会让网络学到噪声。
